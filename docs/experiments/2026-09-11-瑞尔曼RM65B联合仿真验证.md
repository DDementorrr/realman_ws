# 瑞尔曼 RM65B 联合仿真验证

日期：2026-09-11。环境：ROS 2 Jazzy、MoveIt 2.12.4、Gazebo Sim 8.11.0，空世界，
无 RViz 的服务器模式用于自动回归。

## 启动与静态检查

```bash
ros2 launch manipulation_bringup realman_moveit_gz.launch.py use_rviz:=false headless:=true
/home/ww/scripts/verify_realman_gz_runtime.sh
```

观测到：

- `RM65BGazeboSystem` 初始化并激活；
- `joint_state_broadcaster` 与 `rm65b_arm_controller` 均为 active；
- `/move_action`、`/execute_trajectory` 和 FollowJointTrajectory action 存在；
- 六个关节均出现在 `/joint_states`；
- 初始反馈与项目姿态 `[0, 0.5, -1.0, 0, 0.5, 0]` 一致，静止误差处于数值噪声量级；
- controller manager 明确订阅隔离的 `/robot_description_gazebo`。
- 默认 RViz 路径另行启动成功：OpenGL 4.5 初始化、RM65B 模型加载、规划组 `rm65_arm`
  建立 MoveGroup 连接，交互标记服务完成初始化。

## 规划与执行用例

从初始末端位姿附近发布一个空世界目标：位置 `[-0.07, 0.0, 0.78]` m，姿态四元数
`[0.0, 0.0, 1.0, 0.0]`，参考系 `world`。日志显示：

- KDL IK 和 OMPL RRT-Connect 被实际加载；
- 规划成功，单次日志规划时间约 0.0114 s；
- 轨迹发送到 `rm65b_arm_controller` 并被接受；
- Gazebo controller 报告 `Goal reached, success!`；
- MoveIt 轨迹执行最终状态为 `SUCCEEDED`，目标执行器报告到达成功。

这只是一个确定性回归点，不构成规划器性能排名，也不说明其他姿态、障碍场景或随机种子
具有相同结果。

## 告警和残余风险

- KDL 提示根链接 `base_link` 含惯量；KDL 不使用根惯量，但不影响本次运动学规划。
- 未配置 3D 传感器时 MoveIt 会报告没有 Octomap 插件；空世界阶段符合预期。
- Ctrl+C 时 Gazebo 接收 SIGINT 后退出码为 -2，MoveGroup 在 5 秒后被 launch 升级为
  SIGTERM；检查确认没有遗留运行进程。该现象不影响本次执行成功，但应在长期无人值守运行前
  单独优化停止流程。
- 日志确认了 RViz 数据链和交互标记，但屏幕中的网格方向、外观以及 Gazebo/RViz 同步观感
  仍需用户在本机进行一次人工视觉确认。

## 结论

RM65B 裸臂的 `目标 → MoveIt/OMPL → FollowJointTrajectory → gz_ros2_control → Gazebo反馈`
路径通过一次端到端仿真验证。实机驱动、夹爪、相机和移动平台仍未验收，不能据此上电运动。
