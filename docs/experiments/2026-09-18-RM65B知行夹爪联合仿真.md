# 2026-09-18 RM65B 与 CTM2F110 夹爪联合仿真实验

## 问题与环境

验证 ROS1 模型转换后的 `RM65B + CTM2F110` 是否能在 Gazebo Harmonic 运动、
把关节状态同步给 MoveIt/RViz，并通过 MoveIt 一次规划拆分给手臂和夹爪控制器。
环境为 Ubuntu 24.04 WSL2、ROS 2 Jazzy、Gazebo Sim 8.11.0、MoveIt 2 Jazzy。
实验全部是仿真，未连接实机。复现实验需运行
`ros2 launch manipulation_bringup realman_moveit_gz.launch.py with_gripper:=true
headless:=true use_rviz:=false`；图形启动单独去掉后两个参数。

## 观测与结果

| 检查 | 观测 | 结论 |
|---|---|---|
| ROS2 资产包 | 四个相关包 `colcon build --symlink-install` 成功；两个组合 Xacro、`check_urdf` 成功 | 静态通过 |
| 启动门控 | Gazebo 生成后配置并激活 `joint_state_broadcaster`、`rm65b_arm_controller`、`ctm2f110_hand_controller`；MoveIt 注册两个 FollowJointTrajectory 映射 | 通过 |
| DART 反例 | 主动关节 action 报成功但位置仍约 `0`；左内指关节停在 `-1 rad` | 不接受，已换专用物理 world |
| Bullet Featherstone | 主动关节到 `0.3000019 rad` 时，外指/关节约 `+0.300002 rad`，内指约 `-0.300002 rad` | 联动通过 |
| MoveIt 夹爪组 | `rm65_hand` 从约 `0.6` 规划执行到约 `0.4 rad`，反馈约 `0.408 rad`，处于请求的 `±0.01 rad` 容差内 | 通过 |
| MoveIt 联合组 | 七个主动关节目标全部约束后，`rm65_arm_hand` action 为 `SUCCEEDED`；手臂 `joint1≈0.09884 rad`，夹爪 `≈0.49222 rad`，各目标在 `±0.01 rad` 内 | 同一请求的双控制器执行通过 |
| 运行检查 | `verify_realman_gz_runtime.sh` 和 `verify_realman_gripper_gz_runtime.sh` 均 PASS；后者检查五个从动关节相对主关节误差不超过 `0.02 rad` | 通过 |
| 图形启动 | 不加 headless 时 Gazebo GUI 启动；RViz 2 日志显示 OpenGL 4.5、MotionPlanning 加载 `rm65_arm` 并连接 MoveGroup | 进程/插件启动通过；未在本次自动化中人工拖拽验收 |
| 网格资源路径 | Gazebo `/gazebo/resource_paths/get` 同时返回 RM 描述包和 `robot_changingtek_description` 的安装 share 父目录 | 资源搜索路径通过；未人工逐面检查渲染 |
| 默认裸臂回归 | 不带 `with_gripper` 启动后，原有运行检查 PASS；`rm65_arm` 的规划与执行日志为 `SUCCEEDED`，`/joint_states` 仅有 `joint1` 至 `joint6`，静止反馈约为 `(0.09946, 0.49945, -0.99382, -0.00144, 0.50289, -0.00834) rad` | 默认模型与控制器路径未被夹爪模式替换；本项未重新进行 RViz 人工拖拽 |

实验中的关节目标是空世界中的**项目仿真值**，不是实机允许位姿。
若对联合组只约束 `joint1`，规划器会自由选择其余臂关节；一次探索性实验中其它关节确实
偏离原位。最终验收请求显式约束了六个臂关节和夹爪主动关节，不能把前者作为操作范例。

## 结论与建议

当前可以把此模型作为 RM65B 末端夹爪的 MoveIt/Gazebo **研究用仿真适配**；
不能标记为 CTM2F110E 实机适配。下一步应由使用者确认铭牌、厂家图纸和转接板尺寸，
在更新挂载变换和真实碰撞模型后重复上述静态、动态、GUI 和安全检查。需要抓取力或接触
真实性时，必须增加载荷、摩擦和力控实验，而非仅凭关节位置 action 成功。
两种启动模式在本次终端 Ctrl-C 退出时，Gazebo 以 SIGINT 状态退出，`move_group`
未在 5 秒内自行退出而被 launch 发送 SIGTERM；这是**关停阶段**的观察，不等于上述执行
失败，但仍应作为后续生命周期清理问题跟踪。
