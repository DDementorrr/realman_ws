# Codex 本地会话恢复记录

日期：2026-09-03

## 现象

切换登录方式后，Codex 的历史列表只显示新会话，但旧会话 JSONL、会话索引、状态数据库和本地记忆数据库仍然存在。

## 根因

旧线程 `01a05c23-7405-7230-b61b-db47326f0829` 记录的模型提供方为 `custom`，新登录方式使用 `openai`。当前 App Server 在未显式指定 provider 列表时，只返回当前已配置 provider 的线程，因此旧线程被默认过滤。

旧会话完整性检查结果：

- JSONL 可完整解析，共 497 条记录，未发现解析错误。
- 历史投影包含 4 个已完成回合和 165 个可展示条目。
- `session_index.jsonl` 中仍有旧线程索引。
- 本地记忆数据库中仍有该线程的阶段一记忆输出，并已被选入阶段二。

## 恢复操作

1. 在 `~/.codex/recovery-backups/2026-09-03-provider-migration/` 保存会话、索引、配置、SQLite 数据库和记忆文件的恢复前副本。
2. 仅将旧线程的 provider 元数据从 `custom` 迁移为 `openai`。
3. 不修改用户消息、助手消息、工具输出或回合结构。

## 验证

恢复后验证结果：

- App Server 使用默认 provider 过滤时已返回旧线程和新线程，共 2 条。
- `codex resume --all` 已从恢复前的 `1 / 1` 变为 `1 / 2`。
- 旧 JSONL 逐行解析成功，ordinal 连续，记录数保持 497。
- 旧线程仍包含 4 个已完成回合和 165 个历史条目。
- 恢复前备份的 SHA-256 校验全部通过。
