# 2026-09-04 教学规划器与 MoveIt RRT 运行实验

## 实验目的

验证新增教学 planner 在同一障碍问题上的基本正确性，并确认参数化 FR3 运行链确实选择了
非默认的 OMPL `geometric::RRT`，而不只是 YAML 中出现一个名字。

## 实验 A：二维圆形障碍

问题：

```text
limits = [-2,2]^2
start  = (-1,0)
goal   = ( 1,0)
invalid if ||q|| < 0.45
edge_resolution = 0.02
random_seed = 7
```

起终点有效，但直线经过禁区。执行：

```bash
ros2 run manipulation_core planner_comparison_demo
```

输出：

```text
RRT          solved=true work=25   waypoints=15 length=2.7332
RRT-Connect  solved=true work=29   waypoints=17 length=3.0223
RRT*         solved=true work=2500 waypoints=9  length=2.2327
PRM          solved=true work=221  waypoints=6  length=2.3456
PRM roadmap vertices=300
```

所有返回路径都由单元测试再次逐边离散验证。PRM 同一路网连续完成两个不同目标查询，路网
顶点数不变。

判定：算法机制和路径有效性通过。以上只是一个 seed 的确定性回归结果；树 planner 的
`work` 表示迭代，PRM 表示图搜索展开，不能横向解释成速度。RRT-Connect 在这个样本中比
基础 RRT 路径更长，也恰好说明单次随机结果不等于算法的一般排名。

## 实验 B：MoveIt 可用 planner 枚举

在 FR3 运行期间调用 `/query_planner_interface`，MoveIt 返回：

```text
KPIECEkConfigDefault
LazyPRMstarkConfigDefault
PRMkConfigDefault
PRMstarkConfigDefault
RRTConnectkConfigDefault
RRTkConfigDefault
RRTstarkConfigDefault
```

判定：单臂组的 7 个配置均被 MoveIt 识别。相同配置已静态验证应用于左右臂和 `both_arms`。

## 实验 C：成熟 OMPL RRT 的 FR3 规划执行

启动：

```bash
ros2 launch manipulation_bringup franka_moveit_gz.launch.py \
  variant:=fr3 planner_id:=RRTkConfigDefault planning_time:=5.0
```

运行时参数确认 adapter 的 `planner_id` 为 `RRTkConfigDefault`。从当前 link8 位姿保持四元数，
将 x 从约 0.307 m 平移到 0.327 m。关键日志：

```text
Planner configuration 'fr3_arm[RRTkConfigDefault]'
will use planner 'geometric::RRT'
Motion plan was computed successfully
fr3_arm_controller: Goal reached, success
Completed trajectory execution with status SUCCEEDED
Target reached successfully
```

`verify_franka_gz_runtime.sh fr3` 同时确认硬件 active、控制器 active、7 个 position interface
claimed、action 存在、规划/仿真描述隔离和 `fr3_arm` group 存在。

判定：非默认成熟 OMPL RRT 从配置、请求、规划到 Gazebo 执行全链通过。人工 Ctrl-C 后复查
无活动 Gazebo/ROS 节点。

## 建议的正式比较

当前实验不能回答哪种 planner 对 FR3 最好。下一轮应建立至少三类 PlanningScene：开放空间、
桌面障碍、窄通道；每类固定 10 组 start/goal，每个 planner 运行至少 30 个 seed，报告成功率、
首次解时间、P50/P95、路径长度、最小净空、碰撞检查数和执行结果。
