# 2026-09-04 FR3 单臂与固定 FR3 Duo 运行实验

## 实验目的

验证官方 FR3 几何在当前 ROS 2 Jazzy/Gazebo Harmonic 环境中，能够按严格启动次序初始化，
并从 RViz/参数目标经过 MoveIt 到 Gazebo controller 完成真实仿真执行；双臂要同时验证独立
控制和一次 14 轴协调规划。

## 共同条件

```text
franka_description: 2.9.0 / 7aeeddc449edf8d62b594f9e36a81da53e7796f9
MoveIt: 2.12.4
Gazebo Sim: 8.11.0
hands: false
initial q: [0, -pi/4, 0, -3pi/4, 0, pi/2, pi/4]
```

启动世界时不带 `-r`，控制器配置完成后才解除暂停并激活。

## 实验 A：单 FR3

启动：

```bash
ros2 launch manipulation_bringup franka_moveit_gz.launch.py variant:=fr3
```

观测：

- `Fr3GazeboSystem` active；
- joint_state_broadcaster 与 fr3_arm_controller active；
- 7 个 position command interface claimed；
- `/joint_states` 初始值等于 ready q，速度近零，无腕部自由坠落；
- MoveIt 识别 `fr3_arm`、KDL、OMPL 和控制器；
- 在当前 link8 位姿基础上将 x 从约 0.307 m 改为 0.327 m、保持姿态，规划成功；
- 控制器接收 action、返回 `Goal reached, success`；
- MoveIt trajectory execution 返回 `SUCCEEDED`，adapter 返回 target reached。

判定：通过。

## 实验 B：固定 FR3 Duo 启动和独立执行

启动：

```bash
ros2 launch manipulation_bringup franka_moveit_gz.launch.py variant:=fr3_duo
```

启动观测：

- `Fr3DuoGazeboSystem` active；
- joint_state_broadcaster、left/right controller 均 active；
- 14 个 position interface claimed；
- MoveIt 识别 `left_arm`、`right_arm`、`both_arms`；
- 初始左右 link8 约为 `(0.455,+0.355,0.468)`、`(0.455,-0.355,0.468)`；
- 左、右独立 target adapter 分别执行 2 cm 小位移，两个 controller 各自返回成功。

判定：通过。

## 实验 C：14 轴协调规划与双控制器执行

输入（frame `base`）：

```text
left position  = (0.475,  0.355, 0.468)
left quaternion= (0.707, -0.556,  0.147,  0.412)
right position = (0.475, -0.355, 0.468)
right quaternion=(0.893, -0.107, -0.188, -0.395)
```

依次发布到 `/manipulation/dual/left_target_pose` 与
`/manipulation/dual/right_target_pose`，再调用：

```bash
ros2 service call /manipulation/dual/plan_execute std_srvs/srv/Trigger '{}'
```

关键观测：

```text
Planner configuration 'both_arms' -> geometric::RRTConnect
Motion plan was computed successfully
sending trajectory to left_fr3_arm_controller
sending trajectory to right_fr3_arm_controller
left controller: Goal reached, success
right controller: Goal reached, success
Completed trajectory execution with status SUCCEEDED
Trigger response: success=True, coordinated trajectory executed
```

判定：通过。一次复合规划被正确映射到两个控制器，两侧均返回成功。

## 异常/噪声分类

- RViz trajectory visualization 执行时偶发 `No robot state or robot model loaded`；同一时刻
  RobotModel 已在 MotionPlanning 加载，Gazebo/joint_states/action 均成功。判为 RViz display
  层问题，不影响执行判定；保留后续清理。
- 人工 Ctrl-C 后 Gazebo exit `-2`，move_group 5 秒未结束后收到 SIGTERM。退出前所有实验已
  成功，这是关停行为，不能倒推为运行期崩溃；最终一次退出后刷新 ROS daemon 并检查进程，
  未发现活动 Gazebo server/GUI 或 ROS 节点。
- controller manager 关停时报告 async publish failure 统计，不影响此前 action result。

## 结论和建议

1. 初始姿态/腕部下坠问题已由仿真描述分离、ready initial value 和暂停门控解决；
2. FR3 单臂、Duo 两个独立臂和 Duo 协调执行链均可用；
3. 下一实验应添加 PlanningScene 障碍和跨臂窄通道，统计规划成功率/耗时；
4. 再下一阶段实现相对末端位姿的全路径约束与 attached object；
5. 真实 Duo 前先实现官方 effort controller contract、实时条件和急停/限幅，不直接迁移
   Gazebo position controller。
