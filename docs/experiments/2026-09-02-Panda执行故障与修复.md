# 实验报告：Panda 规划成功但执行 ABORTED

## 现象

RViz 中拖动 Panda 末端后规划动画正常，但执行失败。关键日志为：

```text
panda_arm_controller started execution
Action client not connected to action server: panda_hand_controller/gripper_cmd
Failed to send trajectory part 2 of 2
Completed trajectory execution with status ABORTED
```

## 根因

规划器已生成有效轨迹，手臂控制器也接受了第一段 trajectory。官方 Panda demo 默认加载 `gripper_moveit_controllers.yaml`，因此 MoveIt 还会管理 `panda_hand_controller`。执行时夹爪 action server 尚未连接（启动竞态或控制器尚未完成激活），第二段发送失败后，TrajectoryExecutionManager 会取消已发送的手臂轨迹并将整体结果标记为 ABORTED。

这不是 OMPL、IK 或 RViz 拖动规划失败。随后检查确认 `ros2_control` 三个控制器可以正常激活，`/panda_hand_controller/gripper_cmd` 也能在完整启动后出现。

## 修复

1. Level 2 当前只验证手臂 A→B，launch 默认改用 `config/moveit_controllers.yaml`，只向 `panda_arm_controller` 执行。
2. MoveIt/RViz 改为在 `panda_arm_controller` spawner 成功退出后启动，手臂路径不再依赖可选夹爪 action server。
3. 补齐并确认 `ros2_control`、`ros2_controllers`、`controller_manager`、关节状态/轨迹控制器和 `parallel_gripper_controller` 已安装。

## 验证

- `colcon build --packages-select moveit_resources_panda_moveit_config --symlink-install`：成功。
- 三个控制器状态：`active`。
- `/execute_trajectory`（controller `panda_arm_controller`）：`SUCCEEDED`，MoveIt error code `1`。
- `/panda_arm_controller/follow_joint_trajectory`：`SUCCEEDED`，`Goal successfully reached`。

本次官方 Demo 默认使用 `ros2_control_hardware_type:=mock_components`。因此上述成功证明的是 MoveIt 到 ros2_control FakeSystem 的执行链路；它不等同于 Gazebo 物理仿真或真实硬件运动已经验收。

## 非阻塞警告

- `No 3D sensor plugin(s) defined`：当前阶段不做感知/Octomap，可忽略；进入避障阶段再配置传感器。
- `recognize_objects` action 不可用：当前未启用目标识别，预期现象。
- `RvizVisualToolsGui` 插件缺失：只影响可选 RViz 面板，不影响规划和执行。
- WSL2 无 FIFO 实时调度权限：FakeSystem 演示可接受；真实硬件控制前需单独处理实时内核/权限。
- Panda 根 link 惯性 KDL 警告：模型解析仍成功；若使用 KDL 相关功能，可增加 dummy root link。
