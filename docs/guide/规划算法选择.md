# MoveIt/OMPL 规划算法选择与实验指南

## 当前可选 planner

FR3 单臂、左右单臂和 `both_arms` 均开放：

| planner_id | 建议用途 |
|---|---|
| `RRTConnectkConfigDefault` | 默认在线点到点，先取得可靠可行解 |
| `RRTkConfigDefault` | 学习单树行为和建立基础对照 |
| `RRTstarkConfigDefault` | 给更长时间观察路径代价改善 |
| `PRMkConfigDefault` | 静态场景重复查询实验 |
| `PRMstarkConfigDefault` | 静态场景、多查询和路径质量实验 |
| `LazyPRMstarkConfigDefault` | 碰撞检查昂贵时的延迟验证实验 |
| `KPIECEkConfigDefault` | 研究投影引导覆盖，需关注投影质量 |

RViz MotionPlanning 面板可以选择 planner。参数化目标接口可在启动时指定：

```bash
ros2 launch manipulation_bringup franka_moveit_gz.launch.py \
  variant:=fr3 planner_id:=RRTstarkConfigDefault planning_time:=15.0
```

双臂同样使用 `planner_id`：

```bash
ros2 launch manipulation_bringup franka_moveit_gz.launch.py \
  variant:=fr3_duo planner_id:=RRTConnectkConfigDefault
```

错误 planner ID 会在 launch 初期被拒绝，不会悄悄回落到另一个算法。

## 公平比较规则

同一次对比必须固定：

- 完全相同的 URDF/SRDF、PlanningScene 和 allowed collision matrix；
- 相同 start、goal constraint、IK seed 策略；
- 相同 planning time、attempts、碰撞分辨率；
- 同一机器负载条件；
- 仅改变 planner 及它必须的专有参数。

每个问题至少重复 30–100 次，记录：

```text
success_rate
first_solution_time
total_planning_time
joint_space_path_length
end_effector_path_length
minimum_clearance
trajectory_duration
maximum velocity / acceleration
execution result
```

随机算法应报告中位数、P95 和分布，不能只挑最好的一次。RRT* 的“最终解”和“首次解”必须
分开记录。PRM 的建图时间和查询时间也必须分开。

## 场景化起始选择

1. 普通单臂/双臂点到点：先用 RRT-Connect；
2. 可行但路径绕行明显：先 shortcut/时间参数化，再比较 RRT*；
3. 固定工作站反复在多个工位间移动：比较 PRM/PRM* 的预处理摊销；
4. 碰撞检测特别昂贵：比较 LazyPRM*；
5. 窄通道：增加时间并比较多种 sampler/planner，重点统计成功率；
6. 工艺要求 TCP 严格直线：使用 Pilz LIN 或笛卡尔路径，不要期待 RRT 自然生成直线；
7. 需要平滑/净空/自定义代价：研究 STOMP/CHOMP 或优化型 planner；
8. 目标经常变化且响应优先：可研究 MoveIt 多 pipeline 并行首解/择优，但要控制 CPU 资源。

## 失败解释

- 所有 planner 都立即失败：优先检查 start collision、IK、frame、约束和模型；
- 只有某随机 planner 偶发失败：增加重复次数，检查超时、窄通道和采样效率；
- Plan 成功但 Execute 失败：检查 controller/action/起点容差，不属于换 planner 能解决的问题；
- 路径有效但动作难看：区分几何路径、shortcut、时间参数化和控制器跟踪四个阶段。
