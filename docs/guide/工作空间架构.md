# 工作空间分层与源码管理

## 1. 目录和职责

本轮将成熟源码实体放入 `manipulation_ws/upstream/`，项目 ROS 包继续位于 `src/`。
打开 `manipulation_ws/manipulation.code-workspace` 可按职责浏览全部组件。
原有包路径保留，避免破坏已有 symlink-install、CMake 缓存和复现实验命令。

| 层次 | 实际位置（相对 manipulation_ws） | 内容与维护方式 |
|---|---|---|
| 成熟算法源码 | `upstream/moveit2`、`upstream/ompl` | 官方固定版本，阅读区，不参与日常 colcon 构建 |
| 厂家 ROS2 源码 | `upstream/realman_ros2` | 瑞尔曼 Humble 固定提交；驱动与旧启动不进入 Jazzy 默认构建 |
| 社区 ROS1 资源 | `upstream/changingtek_ros1` | Gitee ZIP 归档哈希锁定；CTM2F110 原资源只读，不进入 Jazzy 构建 |
| 成熟运行依赖 | `/opt/ros/jazzy` | apt 安装的 MoveIt、OMPL、KDL、ros2_control、Gazebo 相关包 |
| 自建算法 | `src/manipulation_core` | 原理验证、教学最小实现、测试；不依赖 MoveIt/Gazebo |
| 自建集成 | `src/manipulation_moveit_adapter` | 请求、目标、规划组与 MoveIt API 对接 |
| 自建集成 | `src/manipulation_bringup`、`src/manipulation_demo` | 启动生命周期与交互工具 |
| 上游配套资产 | `src/franka_description`、`src/moveit_resources`、`src/rm_description` | URDF、网格、SRDF 和示例配置；RM 入口是指向固定厂家源码的链接 |
| 自建适配资产 | `src/robot_changingtek_description` | 从 ROS1 CTM2F110 资源迁移的 ament 模型、网格及挂载宏；无实体驱动 |
| 项目配套配置 | `src/robot_franka_moveit_config`、`src/robot_realman_moveit_config`、`src/robot_gazebo` | 规划/控制器映射、仿真描述、world、RViz；含必要适配工具 |
| 文档和验证 | `../docs`、`../scripts` | 教材、来源、报告、验收命令 |
| 生成物 | `build`、`install`、`log` | 构建与运行产物，不作为源码编辑入口 |

这里同时区分“谁维护”和“做什么”：厂家模型虽来自成熟上游，其职责仍是资产；项目配置虽
自主维护，也不等于自行实现了规划算法。包内部可以同时包含配置与适配脚本，不必为分组强拆 ROS 包。

## 2. 实际运行链

```text
RViz / 项目交互工具
  → manipulation_moveit_adapter / MoveGroup 请求
  → MoveIt RobotModel / PlanningScene / KDL IK
  → MoveIt OMPL 接口 → OMPL 规划器
  → MoveIt 时间参数化 / 执行管理
  → ros2_control → gz_ros2_control → Gazebo
  → joint_states / TF → RViz
```

教学 `manipulation_core` 不在这条执行链中。学习时先用其短代码理解原理，再沿成熟源码理解
状态管理、碰撞、数值边界、插件和控制器。当前读本地源码，运行对应上游版本的 Jazzy 二进制。

## 3. 版本与复现

资产使用 `manipulation_jazzy.repos`（导入到 `src`）；成熟算法阅读区使用 `upstream.repos`
（导入到 `upstream`）。两个 manifest 的目标根不同，不能对着 `src` 导入阅读区 manifest。
ChangingTek 的 Git 通道在本环境超时，本次使用 Gitee `master.zip`，由
`upstream/changingtek_ros1.归档锁定.md` 的 SHA-256 锁定，并由独立脚本重建；
**没有**可验证的提交号，不能将其混写进 Git manifest 并假称 commit pin。

```bash
cd /home/ww/manipulation_ws
vcs import upstream < upstream.repos
/home/ww/scripts/prepare_realman_model_source.sh
if [ ! -e upstream/changingtek_ros1 ]; then /home/ww/scripts/prepare_changingtek_ros1_snapshot.sh; fi
python3 /home/ww/scripts/verify_workspace_architecture.py
source /opt/ros/jazzy/setup.bash
colcon list --base-paths src
colcon build --base-paths src --symlink-install
```

MoveIt 2.12.4：`1ade0e9dcf50dbbbc3a984b995c786cf12736235`。
OMPL 1.7.0：`eabb4d0f825666e4553a2ec0ecb9c7a5a33637dd`。
瑞尔曼 ROS2 Humble：`c941b565e4f9174afa36561f143ef5fbbb744750`。
这次没有把所有传递依赖都复制进仓库。KDL、FCL、Eigen、控制器仍作为系统依赖使用；
当学习深入这些模块时，可按相同策略增加固定版本源码。

现有 `moveit_resources` 中 Panda 的 controller YAML 和 demo launch 有项目历史修改；固定
上游 commit 的 manifest 本身不能重建这些修改。必须保留并单独备份补丁。本轮验证工具会
报告资产工作树状态，不执行覆盖或重置。Franka 厂家模型保持原样。

## 4. 编译上游与阅读上游的区别

本次完成的是官方源码本地化、版本锁定和学习入口，不是替换正在使用的共享库。
直接在本地阅读区修改 C++ 不会改变 RViz 或 move_group 行为。

要开展源码调试，应建立独立构建目录/overlay，核查该 tag 的依赖，使用带调试信息的构建，
确认 `ros2 pkg prefix` 和动态库路径指向新产物，再重建项目适配器并执行 FR3/双臂验收。
上游源码目录没有 `compile_commands.json` 时，IDE 的跳转可能仅靠文本索引；这不代表已经
具备可断点运行的源码构建。当前无需卸载 apt MoveIt。

## 5. 工作规则

- 上游修改先建立研究分支并记录补丁，主参考提交保持可追溯。
- 新功能按职责添加：算法研究到 core，MoveIt 请求映射到 adapter，模型数据到资产包。
- 增加源码后运行架构检查；修改文档后运行公式检查。
- 阅读路线见 [MoveIt 成熟源码导读](MoveIt源码阅读.md)。
