# 工作空间分层与源码管理

## 1. 目录和职责

本工程位于 `/home/ww/realman_ws`，成熟源码实体放入 `upstream/`，项目 ROS 包按对象分组位于
`src/`。ROS 包名和安装接口保持不变，因此目录重组不会改变启动、action 或参数接口。

| 层次 | 实际位置（相对 realman_ws） | 内容与维护方式 |
|---|---|---|
| 成熟算法源码 | `upstream/moveit2`、`upstream/ompl` | 官方固定版本，阅读区，不参与日常 colcon 构建 |
| 厂家 ROS2 源码 | `upstream/realman_ros2` | 瑞尔曼 Humble 固定提交；RM 描述入口为 `src/realman_rm65/rm_description` |
| 社区 ROS1 资源 | `upstream/changingtek_ros1` | Gitee ZIP 归档哈希锁定；仅作为来源和许可证记录 |
| 成熟运行依赖 | `/opt/ros/humble` + `.third_party/gz_ros2_control` | MoveIt、OMPL、KDL、ros2_control、Gazebo Harmonic 相关包 |
| 通用 ROS 2 适配 | `src/ros2_adapters` | MoveIt 请求、启动编排、交互工具和任务演示；不复制上游规划算法 |
| 自建集成 | `src/ros2_adapters/manipulation_moveit_adapter` | 请求、目标、规划组与 MoveIt API 对接 |
| 自建集成 | `src/ros2_adapters/manipulation_bringup`、`src/ros2_adapters/manipulation_demo`、`src/ros2_adapters/pick_place_demo` | 启动生命周期、交互工具和增量 Pick & Place 场景 |
| 上游配套资产 | `src/realman_rm65/rm_description` | 指向 `upstream/realman_ros2/rm_description` 的符号链接 |
| 自建适配资产 | `src/crt_ctm2f110_gripper_visualization/robot_changingtek_description` | 从 ROS1 CTM2F110 资源迁移的 ament 模型、网格及挂载宏 |
| 夹爪实机接口与 SDK | `src/crt_ctm2f110_gripper_visualization/changingtek_gripper_driver` | ROS 2 action/state 包装及 vendor 官方 SDK 快照（头文件、源码、许可证、x86_64/arm64 库），默认 dry-run |
| 项目配套配置 | `src/realman_rm65/robot_realman_moveit_config`、`src/realman_rm65/robot_gazebo` | 规划/控制器映射、仿真描述、world、RViz；含必要适配工具 |
| 文档和验证 | `../docs`、`../scripts` | 教材、来源、报告、验收命令 |
| 生成物 | `build`、`install`、`log` | 构建与运行产物，不作为源码编辑入口 |

这里同时区分“谁维护”和“做什么”：厂家模型虽来自成熟上游，其职责仍是资产；项目配置虽
自主维护，也不等于自行实现了规划算法。包内部可以同时包含配置与适配脚本，不必为分组强拆 ROS 包。

## 2. 实际运行链

```text
RViz / 项目交互工具
  → manipulation_moveit_adapter / MoveGroup 请求
  → MoveIt RobotModel / PlanningScene / KDL IK
  → MoveIt OMPL 接口 → OMPL 规划器
  → MoveIt 时间参数化 / 执行管理
  → ros2_control → gz_ros2_control → Gazebo
  → joint_states / TF → RViz
```

`src/ros2_adapters` 位于这条执行链中，教学算法不在当前迁移仓库的默认构建范围内。运行组合
固定为 Ubuntu 22.04、ROS 2 Humble 和 Gazebo Harmonic；Gazebo 控制插件由
`.third_party/gz_ros2_control` 提供。

## 3. 版本与复现

RealMan 资产使用 `upstream/realman_humble.repos`；成熟算法阅读区使用 `upstream.repos`
（导入到 `upstream`）。两个 manifest 的目标根不同，不能对着 `src` 导入阅读区 manifest。
ChangingTek 的 Git 通道在本环境超时，本次使用 Gitee `master.zip`，由
`upstream/changingtek_ros1.归档锁定.md` 的 SHA-256 锁定，并由独立脚本重建；
**没有**可验证的提交号，不能将其混写进 Git manifest 并假称 commit pin。

```bash
cd /home/ww/realman_ws
bash scripts/import_upstream.sh
bash scripts/prepare_realman_model_source.sh
source /opt/ros/humble/setup.bash
colcon list --base-paths src
colcon build --symlink-install
```

MoveIt 2.12.4：`1ade0e9dcf50dbbbc3a984b995c786cf12736235`。
OMPL 1.7.0：`eabb4d0f825666e4553a2ec0ecb9c7a5a33637dd`。
瑞尔曼 ROS2 Humble：`c941b565e4f9174afa36561f143ef5fbbb744750`。
这次没有把所有传递依赖都复制进仓库。KDL、FCL、Eigen、控制器仍作为系统依赖使用；
当学习深入这些模块时，可按相同策略增加固定版本源码。

本仓库不把 Panda、Franka 或教学算法作为 RM65B 项目的运行依赖；相关历史资料如仍存在于
主工作空间，应按历史阅读材料维护，不能作为本工程的构建前提。验证工具只检查本仓库声明的
RealMan、CTM2F110、适配层和 Harmonic 控制插件，不执行覆盖或重置。

## 4. 编译上游与阅读上游的区别

本次完成的是官方源码本地化、版本锁定和学习入口，不是替换正在使用的共享库。
直接在本地阅读区修改 C++ 不会改变 RViz 或 move_group 行为。

要开展源码调试，应建立独立构建目录/overlay，核查该 tag 的依赖，使用带调试信息的构建，
确认 `ros2 pkg prefix` 和动态库路径指向新产物，再重建本工程适配器并执行 RM65B/CTM2F110 验收。
上游源码目录没有 `compile_commands.json` 时，IDE 的跳转可能仅靠文本索引；这不代表已经
具备可断点运行的源码构建。当前无需卸载 apt MoveIt。

对象目录清单、ROS 2 SDK 构建边界和最近一次验证结果见
[2026-09-23 目录与文档复核报告](../build-reports/2026-09-23-RM65B与CTM2F110目录及文档复核.md)。
