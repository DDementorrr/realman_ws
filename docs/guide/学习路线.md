# MoveIt 与 Manipulation 学习路线

## 先建立系统地图

```text
URDF/XACRO + SRDF
        ↓
robot_state_publisher / TF2
        ↓
MoveIt RobotModel + PlanningScene
        ↓
IK（kinematics.yaml）
        ↓
OMPL/CHOMP/Pilz/STOMP（规划 pipeline）
        ↓
RobotTrajectory
        ↓
TrajectoryExecutionManager
        ↓
FollowJointTrajectory action
        ↓
ros2_control controller → hardware/mock system
```

Panda 资源包提供模型和配置，`/opt/ros/jazzy` 提供 MoveIt 库与节点，`demo.launch.py` 负责把它们接线；这三层要分开理解。

注意：官方 Panda Demo 默认的 `mock_components` 是控制器测试后端，不是 Gazebo。先用它验证 action 和执行管理器，再把 robot description、ros2_control hardware plugin 和 `ros_gz` 接入 Gazebo，才能验证仿真动力学/关节状态闭环。

## 建议顺序

### 阶段 1：ROS 2 基础

掌握 node、topic、service、action、parameter、launch、package、workspace、overlay，以及 `source /opt/ros/jazzy/setup.bash` 与 `source install/setup.bash` 的作用。用 `ros2 node/topic/action/service list|info|echo` 观察 Panda demo。

### 阶段 2：机器人模型与坐标

阅读 Panda `config/panda.urdf.xacro`、`panda.srdf`、`kinematics.yaml`、`joint_limits.yaml`。理解 link/joint、revolute、joint limit、inertial、visual/collision、planning group、end effector、virtual joint。用 `xacro` 展开 URDF，用 TF2 检查 `world → panda_link0 → ... → panda_hand`。

### 阶段 3：MoveIt 规划

先使用 RViz MotionPlanning 面板，再阅读 `moveit2_tutorials` 中 MoveGroupInterface、PlanningScene、运动学和轨迹执行示例。教程用于学习和复制最小代码，不作为产品运行时依赖；选择与 Jazzy 兼容的教程版本，教程工作空间与产品工作空间分开。

### 阶段 4：控制执行

理解 `ros2_control_node`、hardware interface、controller_manager、JointTrajectoryController、GripperActionController，以及 MoveIt 的 controller YAML 如何映射 action 名称和关节集合。先用 `ros2 control list_controllers`、`ros2 action list`，再用 action CLI 做最小轨迹测试。

### 阶段 5：项目化封装

在 `manipulation_core` 定义 `RobotState`、`Pose`、`Trajectory`、`Planner`、`Controller` 接口；MoveIt/Gazebo 只在 adapter 中出现。先实现 Panda 7 自由度 A→B，再用 Fanuc M-10iA 或 UR5/UR5e 验证核心没有绑定关节数和具体机型。

## 核心知识清单

- 刚体变换、齐次变换、旋转表示、四元数和 TF2
- 正/逆运动学、Jacobian、冗余自由度、IK 可行性
- 关节空间与笛卡尔空间规划、碰撞检测、PlanningScene
- 采样规划（RRT/RRT-Connect）、轨迹时间参数化、速度/加速度限位
- ROS 2 action 生命周期、反馈、取消和超时
- ros2_control 的 command/state interface 与控制器资源声明
- URDF/SRDF/XACRO、CMake/ament、colcon、rosdep 和 overlay 工作空间

## 可跟踪实践

1. 仅启动 Panda，记录节点、topic、TF、controller 和 action 清单。
2. 在 RViz 规划 10 个不同目标，记录 planner、规划时间、轨迹点数和执行结果。
3. 修改 `ompl_planning.yaml` 的规划时间/算法，比较成功率和轨迹长度。
4. 单独调用 arm action，再调用 MoveIt `/execute_trajectory`，理解两层接口差异。
5. 最后编写一个 C++ A→B 节点，把 MoveIt 调用封装到 adapter，并保留可替换的核心接口。
