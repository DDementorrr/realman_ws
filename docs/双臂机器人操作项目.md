# 双臂机器人 Manipulation 项目
## 当前工程纲领、已实现基线与后续路线

### 1. 项目定位

本项目面向数字孪生驱动的移动双臂机器人作业系统，研究重点为**双臂作业系统的任务执行、运动规划与控制**。

整体系统划分为三个主要部分：

```text
自研数字孪生平台
        │
        │ API / 状态与任务信息
        ↓
机器人控制器（PC）
        │
        ├── 移动平台接口
        │
        └── 双臂 Manipulation 系统
                │
                ├── 感知
                ├── 任务规划
                ├── 运动规划
                ├── 轨迹生成
                └── 控制执行
```

其中：

- **数字孪生平台**：负责大尺度物理环境建模、位置信息、局部场景信息、任务下发及机器人状态可视化。
- **移动平台**：负责将双臂作业系统运送至指定作业位置，承担类似 AGV 的移动功能。
- **双臂作业系统**：负责具体作业任务，是本项目主要研究对象。
- **机器人控制器 PC**：负责连接数字孪生平台、移动平台、双臂系统及感知设备，承担任务解析、规划与控制。

## 2. 里程碑状态

Level 2 目标为在仿真环境中完成**单臂 A→B 的运动规划与控制验证**。该目标已经由 Panda 和最新 FR3 两条路径验收。FR3 现为 7 自由度主参考，Panda 保留为 MoveIt 回归机型；瑞尔曼 RM65B 是当前 6 轴实机接入目标，已完成裸臂及基于 CTM2F110 社区模型的夹爪联合仿真。实体系统所称 CTM2F110E 与模型是否一致待核对。仿真通过不代表实机控制已经验收，自由度数不得写入核心接口假设。

在不改变 Level 2 验收定义的前提下，工程已建立 Level 3 的固定式 FR3 Duo 研究脚手架：左右臂独立规划、14 轴复合规划、Gazebo 双控制器执行和 RViz 同步已验收；共同物体闭链约束、抓取接触、力分配和真实双臂控制仍是后续研究，不得提前宣称完成。

### 目标流程

```text
给定起始位姿 A
        ↓
机器人状态初始化
        ↓
目标位姿 B
        ↓
逆运动学求解
        ↓
成熟运动规划算法
        ↓
轨迹生成
        ↓
控制器执行
        ↓
机械臂到达 B
```

### Level 2 不包含、后续阶段处理

- RGB-D / 深度相机
- 障碍物感知
- 复杂避障
- 双臂共同物体闭链协同与力控制
- 抓取与接触操作
- 数字孪生平台 API
- 真实机械臂部署

上述内容作为后续阶段扩展方向。

# 3. 总体软件架构

工程采用**核心控制逻辑与具体仿真环境解耦**的架构。

### 当前代码的所有权与运行边界

成熟实现、教学实现和配套资产必须显式区分：

- `manipulation_ws/upstream/`：官方 MoveIt 2.12.4、OMPL 1.7.0 源码，独立提交锁定，只读学习，不参与默认构建；当前运行仍使用 Jazzy 系统二进制包。

# 5. 第一阶段软件数据流

```text
Start Pose A
     │
     ↓
Robot State
     │
     ↓
Inverse Kinematics
     │
     ↓
Goal Joint State
     │
     ↓
Motion Planner
     │
     ↓
Trajectory
     │
     ↓
Controller
     │
     ↓
Robot Adapter
     │
     ↓
Gazebo Harmonic
```

规划器、轨迹生成和控制器独立组织，后续可以替换不同算法或不同执行后端。

### 联合仿真的描述与状态边界

MoveIt/RViz 与 Gazebo 共享同一套 link、joint、limit 和 frame 语义，但 ros2_control hardware backend 必须隔离：

```text
MoveIt/RViz model description  -> /robot_description
GazeboSystem description       -> /robot_description_gazebo
Gazebo controller feedback     -> /joint_states -> MoveIt/RViz
```

`/joint_states` 是联合仿真中唯一的执行状态真值。RViz 负责目标输入、规划交互与状态可视化，不得再生成一套与 Gazebo 并行的 FakeSystem 执行状态。后端话题名和 hardware plugin 差异属于 `robot_gazebo`/`manipulation_bringup` 适配层职责，不得泄漏到 manipulation core。

物理仿真启动时必须先暂停世界，待 hardware 初始化和 controller 配置完成后再解除暂停并激活 controller；MoveIt/RViz 只在 controller 激活成功后启动。任一门控步骤失败时应终止 bringup，不允许进入半初始化运行状态。

# 6. 规划算法与“黑箱拆解”策略

运行路径采用成熟算法；同时在 `manipulation_core` 中保留最小、可测试、可逐式阅读的教学实现。教学实现用于理解和交叉校验，不替代 MoveIt/OMPL 的产品级碰撞、约束规划、插件生态和安全边界。

推荐技术栈：

```text
MoveIt 2
    │
    └── OMPL
         ├── RRT
         ├── RRT-Connect
         ├── RRT*
         ├── PRM / PRM* / LazyPRM*
         └── KPIECE
```

第一阶段重点使用：

- 逆运动学（IK）
- Joint-space / Cartesian-space 目标定义
- RRT-Connect 等成熟采样规划算法
- Trajectory Generation
- Trajectory Execution

教学核心当前包括：标准/Craig 修正 DH、FK、几何 Jacobian、阻尼最小二乘 IK、抽象碰撞
检查、基础 RRT、双向 RRT-Connect、教学 RRT*、可复用 PRM、路径 shortcut、五次时间缩放、
COM Jacobian 重力补偿和关节 PID。算法体由项目依据公开原理重新编写，不复制 OMPL 源码；
实际 FR3 运行仍使用成熟 MoveIt/OMPL。完整推导和成熟库差异见 `docs/textbook/`。

# 7. 机械臂模型

采用成熟串联机械臂进行验证。FR3 是当前 7 自由度主参考；固定 FR3 Duo 是双臂研究参考；Panda 是 MoveIt 回归机型；RM65B 是当前 6 轴实机接入目标；Fanuc M-10iA 测试模型继续用于一般 6 轴架构兼容性检查。

要求：

```text
DOF              = 6 或 7（当前参考实现为 7）
Joint Type       = Revolute
Joint Limits     = 明确配置
Base Frame       = 明确配置
End Effector     = 明确配置
Robot Description= URDF
```

机械臂具体型号不作为核心算法的编译期约束。机型差异应被限定在 robot description、SRDF、MoveIt 配置、controller YAML 和 hardware/simulator adapter 中。

推荐使用已有成熟模型进行开发验证，例如：

```text
FR3（7 自由度主参考机型）
固定式 FR3 Duo（双臂研究脚手架）
Panda（7 自由度回归机型）
UR5 / UR5e、Fanuc M-10iA（6 轴架构验证）
KUKA 系列
```

核心代码不得依赖具体型号。

# 11. FR3 单臂与双臂数据流

```text
RViz marker / PoseStamped / interactive console
          ↓
manipulation_moveit_adapter
          ↓
MoveIt: IK + PlanningScene + OMPL + time parameterization
          ↓
MoveIt controller manager（按 joint set 拆分）
          ↓
single: fr3_arm_controller
duo: left_fr3_arm_controller + right_fr3_arm_controller
          ↓
gz_ros2_control -> Gazebo physics
          ↓
/joint_states -> MoveIt/RViz/TF
```

FR3 Duo 提供 `left_arm`、`right_arm`、`both_arms` 三个规划组。独立话题用于单侧任务；协调接口缓存左右目标，再通过 `/manipulation/dual/plan_execute` 对 `both_arms` 一次规划和执行。

# 12. 仿真与实机能力边界

当前 Gazebo FR3/FR3 Duo 使用 position command interface，目的是验证规划、控制器映射和同步可视化。Franka 官方公开的固定 FR3 Duo 实机 bringup 当前只支持双臂 torque/effort command path。后续实机迁移必须增加厂家 hardware adapter、实时 effort controller、安全状态机和实机验收，不得复用 Gazebo position YAML 声称兼容。

# 23. 当前阶段执行原则

1. **固定 Ubuntu 24.04 + ROS 2 Jazzy + Gazebo Harmonic 作为第一阶段基础环境。**

2. **MoveIt 2 使用 Jazzy 稳定分支，`main` 仅用于新功能跟踪和独立测试。**

3. **核心 Manipulation C++ 代码与 Gazebo、MoveIt、真实机器人及数字孪生平台保持接口解耦。**

4. **Level 2 单臂 A→B 已由 Panda 和 FR3 验收；当前以 7 自由度 FR3 为主参考，Panda
   保留为 MoveIt 回归机型，固定 FR3 Duo 作为 Level 3/5 研究脚手架。**

5. **运行链优先使用成熟的 MoveIt 2 + OMPL；`manipulation_core` 保留可逐式阅读和单元测试
   的教学实现，用于理解与交叉验证，不作为产品级规划器或真实机器人安全控制器。**

6. **机械臂使用成熟 6/7 自由度模型进行验证，核心接口不假定固定关节数，真实机型根据负载、工作空间、安全和成本选择。**

7. **当前主开发环境采用 Native，不建立 Docker-first 架构。**

8. **后续引入视觉、VLA、World Model 等高依赖模块时，再对相关环境进行独立隔离。**

9. **第一阶段结束时形成可复用的 Manipulation Core，为后续避障、双臂协同、任务规划、VLA/World Model 和数字孪生接入提供基础。**

# 24. 当前落地的执行与仿真边界

当前采用两条目标输入路径，但共用同一条规划和执行链：

```text
RViz 交互标记 ─────────────┐
                              ├→ MoveIt move_group
PoseStamped 目标主题 → MoveIt Adapter ┘
                                      ↓
                            controller action
                                      ↓
                               gz_ros2_control
                                      ↓
                         Gazebo Harmonic 物理状态
                                      ↓
                             /joint_states + TF
                                      ↓
                                  RViz 显示
```

在 Gazebo 模式中，Gazebo/控制器反馈是关节执行状态的唯一真值源，RViz 只负责交互目标、规划路径和反馈状态可视化。`mock_components` 仅用于验证 MoveIt—controller 的软件契约，不作为 Gazebo 动力学验收结果。

包职责固定为：

- `manipulation_core`：不依赖 ROS/MoveIt/Gazebo 的教学算法实现和后端无关接口。
- `robot_franka_moveit_config`：项目自有 FR3/固定 Duo SRDF、运动学、规划与控制器映射。
- `robot_gazebo`：仿真模型、Harmonic 控制插件、controller 配置和 world。
- `manipulation_moveit_adapter`：将项目目标接口转换为 MoveIt 规划/执行请求。
- `manipulation_bringup`：仅做节点编排、参数组装和启动就绪顺序。
- `manipulation_demo`：提供交互目标发布和验收入口，不承载规划核心。
- `moveit_resources`：锁定的上游测试/学习资源，项目特有修复应逐步迁移到自有配置包，避免长期维护上游 fork。

PR2 当前定位为 Gazebo Harmonic 模型兼容性实验对象，不是 Level 2 的 MoveIt 主验收机型。其旧 Gazebo Classic 扩展在适配层中被过滤，当前只启用左/右臂、头部与升降轴的位置轨迹控制；移动底盘、传感器和抓手控制需在后续里程碑独立现代化。
