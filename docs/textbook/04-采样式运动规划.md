# 第四章：采样式运动规划、算法族与碰撞检测

## 1. 先分清 MoveIt、OMPL 和 RRT

三者不是同一层级：

```text
MoveIt PlanningPipeline
  ├── RobotModel / PlanningScene / 约束 / 请求与响应 adapter
  ├── planner plugin
  │     └── OMPL interface
  │            ├── RRT
  │            ├── RRT-Connect
  │            ├── RRT*
  │            ├── PRM / PRM*
  │            └── KPIECE / LazyPRM* / ...
  └── 时间参数化、解验证、controller execution
```

- **MoveIt** 是机器人运动规划与执行框架，负责机器人语义、场景、约束、规划器插件和控制器
  接口。
- **OMPL**（Open Motion Planning Library）是采样式运动规划算法库。它提供状态空间、采样、
  最近邻、图/树和众多 planner，但不认识项目里的 FR3 link 名称。
- **RRT** 是一种“快速探索随机树”算法思想；RRT-Connect、RRT* 是不同扩展。
- **FCL/PlanningScene** 负责 MoveIt 路径上的机器人碰撞语义；OMPL 通过状态/边有效性回调
  询问一个状态或运动是否可用。

因此“当前用 OMPL”不能回答“具体选了哪种算法”；还必须看 `planner_id`。

## 2. IK、路径、轨迹不是一回事

IK 只寻找一个目标关节状态。路径规划需要找到连续曲线：

$$
\begin{aligned}
\mathbf{q}(0)&=\mathbf{q}_{\mathrm{start}},\\
\mathbf{q}(1)&=\mathbf{q}_{\mathrm{goal}},\\
\mathbf{q}(s)&\in\mathcal{C}_{\mathrm{free}},\qquad 0\le s\le1.
\end{aligned}
$$

$s$ 是只描述路径进度的参数，不是时间；$\mathcal{C}_{\mathrm{free}}$ 是所有合法且无碰撞的
关节状态集合。三行分别要求路径从起点出发、在终点结束，并且中间每一点都安全。

随后时间参数化才给路径附加 `time_from_start`、速度和加速度。最后控制器才执行轨迹。一个
终点 IK 无碰撞，完全不能证明通向它的整条路径无碰撞。

固定 FR3 Duo 的 `both_arms` 是 14 维配置空间。每次状态检查至少要考虑左臂自碰撞、右臂
自碰撞、左右交叉碰撞和环境碰撞。

## 3. 状态空间、度量和局部连接器

本工程教学核心把状态简化为 `Eigen::VectorXd q`，关节限位形成一个盒状采样域，距离为：

$$
d(\mathbf{q}_a,\mathbf{q}_b)
=
\left\lVert\mathbf{q}_b-\mathbf{q}_a\right\rVert_2
$$

这里 $\mathbf{q}_a$、$\mathbf{q}_b$ 是两个关节状态，$d$ 是所有关节差值的欧氏长度。

这对全转动、单位一致的小实验足够，但成熟库还要处理：

- 连续转动关节在 `-pi/pi` 处的环绕；
- SE(2)、SE(3)、复合空间及其插值；
- 不同关节范围/单位的距离权重；
- 路径约束所形成的低维流形；
- 控制输入和动力学可达性。

教学局部连接器在关节空间做直线插值：

$$
\begin{aligned}
N
&=\left\lceil
\frac{\left\lVert\mathbf{q}_b-\mathbf{q}_a\right\rVert_2}
{r_{\mathrm{edge}}}
\right\rceil,\\
\mathbf{q}_k
&=\mathbf{q}_a+\frac{k}{N}(\mathbf{q}_b-\mathbf{q}_a),
\qquad k=0,1,\ldots,N.
\end{aligned}
$$

$r_{\mathrm{edge}}$ 是允许的最大检查间隔，$N$ 是需要分成的段数，$\mathbf{q}_k$ 是第 $k$
个检查点。先算要切多少段，再逐点做碰撞检查。

每一点交给 `CollisionChecker::isStateValid()`。分辨率太粗会跨过薄障碍；太细会让碰撞检测
成为主要开销。当前实现是离散检查，不宣称连续碰撞保证。

## 4. 基础 RRT：单树快速探索

基础 RRT 从起点建立一棵树：

1. 以 `goal_bias` 概率直接采目标，否则均匀随机采样；
2. 在线性扫描中找到最近树节点；
3. 最多前进 `step_size`；
4. 局部边有效才加入树；
5. 新节点足够接近目标且连线有效时返回。

RRT 的 Voronoi 偏置使大块未探索空间更容易被选中。它适合解释随机树的基本机制，也可以
较快探索高维空间；但单树要自己“撞到”目标邻域，通常不如双树 RRT-Connect 擅长普通的
确定起终点查询。它只追求可行路径，不优化长度和平滑度。

代码：`sampling_planners.cpp` 中的 `RrtPlanner`。

## 5. RRT-Connect：面向单次查询的双树连接

RRT-Connect 分别从 start 和 goal 建树。树 A 朝随机样本走一步后，树 B 会反复朝新节点
贪婪延伸，直到被障碍阻挡或两树连接；然后交换两树角色。

优势：

- 起点和终点都参与探索；
- 对普通机械臂点到点问题通常很快找到第一条可行路径；
- 对 7/14 维关节空间是稳健的默认基线。

代价：

- 路径往往有折线和多余关节运动；
- 不保证最短；
- 狭窄通道仍可能低概率采不到；
- 贪婪连接会做很多边碰撞检查。

这也是当前 FR3/FR3 Duo 的默认 planner。教学实现位于 `rrt_connect.cpp`；实际运行由
OMPL 的 `geometric::RRTConnect` 完成，两份代码互不调用。

## 6. RRT*：把“找到路径”改成“持续改善路径”

RRT* 在加入新节点时不一定选择几何最近节点作为父节点，而会在邻域中选择累计代价最小且
边有效的父节点；随后尝试把已有邻居重新挂到新节点：

$$
c(\mathbf{q}_{\mathrm{new}})
=
\min_{i}
\left[
c(\mathbf{q}_i)+d(\mathbf{q}_i,\mathbf{q}_{\mathrm{new}})
\right]
$$

第一式表示：在所有可连接邻居中，选择“到邻居的已有总代价 + 邻居到新节点的距离”最小者
作为父节点。随后对邻居 $\mathbf{q}_j$ 检查：

$$
c(\mathbf{q}_{\mathrm{new}})+d(\mathbf{q}_{\mathrm{new}},\mathbf{q}_j)
<c(\mathbf{q}_j)
$$

若成立且新边无碰撞，就把 $\mathbf{q}_j$ 改挂到新节点，这一步称为 rewire（重连）。

它通常在找到第一条路径后继续运行，随着样本增加改善指定代价。本教学实现优化关节欧氏
路径长度，使用固定邻域半径、线性最近邻和固定迭代预算，用来观察 choose-parent/rewire，
不宣称复现 OMPL 全部参数、数据结构或理论证明条件。

适合：离线规划、路径质量比首解延迟更重要、有足够时间预算的任务。不适合把很短的超时
设给它，然后仅凭一次运行断言它“不如 RRT-Connect”。

## 7. PRM：先建路网，再回答多次查询

PRM 分为学习阶段和查询阶段：

1. 在自由空间采样 milestone；
2. 尝试连接每个点的近邻，形成无向 roadmap；
3. 把 start/goal 接到路网；
4. 在图上做最短路搜索。

本教学实现的 `PrmPlanner::buildRoadmap()` 可显式预建并保留路网，多个 `plan()` 查询复用
同一图；查询使用 Dijkstra。OMPL PRM 的工程实现具有更成熟的近邻和增量维护，并可使用
启发式图搜索。

适合：静态或变化较少的工作单元中反复查询。初次建图有开销，障碍变化后缓存边可能失效，
需要失效检测或重建。

- PRM* 调整连接策略以获得渐近最优性质；
- LazyPRM* 先假设边可用，只有搜索命中的候选路径才做昂贵碰撞检查，适合碰撞检查非常贵
  且许多边从未用于查询的情况。

## 8. KPIECE：用低维投影指导覆盖

KPIECE 把高维状态投影到低维网格，优先扩展覆盖稀疏或边界单元。若能设计有意义的投影，
它能把探索集中到尚未覆盖的区域；投影选择不当则会把不同的高维状态挤进相同网格，效果
可能变差。当前工程只在 MoveIt/OMPL 配置中开放 KPIECE，没有在教学核心重新实现。

## 9. 算法选择表

| Planner | 结构 | 主要目标 | 最典型优势场景 | 主要代价 |
|---|---|---|---|---|
| RRT | 单树 | 第一条可行路 | 学习、开放高维空间、单次查询 | 目标连接慢，路径粗糙 |
| RRT-Connect | 双树 | 快速可行路 | 机械臂普通点到点、在线重规划 | 不最优，路径依赖随机种子 |
| RRT* | 重连树 | 随时间改善代价 | 离线高质量路径 | 首解/收敛更慢 |
| PRM | 可复用图 | 多次查询 | 静态工作站、重复任务 | 预处理和内存，场景变化处理 |
| PRM* | 渐近最优图 | 多查询+质量 | 静态场景的长期路网 | 更多连接与碰撞检查 |
| LazyPRM* | 延迟验证图 | 减少无用碰撞检查 | 碰撞检查昂贵 | 查询时可能反复修复无效路径 |
| KPIECE | 投影覆盖树 | 覆盖难探索区域 | 有良好低维投影的问题 | 对投影和参数敏感 |
| CHOMP | 梯度轨迹优化 | 平滑/净空代价 | 有合理初始轨迹和距离梯度 | 局部极小、调参 |
| STOMP | 随机轨迹优化 | 无梯度代价下平滑优化 | 复杂自定义代价、平滑轨迹 | 多次 rollout 计算开销 |
| Pilz PTP/LIN/CIRC | 工业运动原语 | 可预测几何运动 | 工艺直线、圆弧、点到点 | 不负责随机搜索绕障 |

“最擅长”是经验起点，不是保证。同一算法在不同机器人、碰撞几何、目标约束和超时下会交换
排名；必须在自己的数据集上重复 benchmark。

## 10. 当前工程到底包含哪些算法

教学核心现在包含：

```text
RrtPlanner
RrtConnectPlanner
RrtStarPlanner       # 教学版路径长度优化
PrmPlanner           # 路网可跨查询复用
isEdgeValid / isPathValid / pathLength / shortcutPath
```

MoveIt/OMPL 运行配置现在开放七个 `planner_id`：

```text
RRTConnectkConfigDefault
RRTkConfigDefault
RRTstarkConfigDefault
PRMkConfigDefault
PRMstarkConfigDefault
LazyPRMstarkConfigDefault
KPIECEkConfigDefault
```

前四种在两层都有对应概念，便于对照；后面三种只使用成熟 OMPL 实现。教学核心并未接入
FR3 执行链，运行时仍由 MoveIt PlanningScene + OMPL 规划，避免把简化碰撞模型误当产品
能力。

## 11. 为什么演示多种规划算法

演示多种算法不是为了制造更多按钮，而是为了训练以下判断：

1. **可行性和质量不同**：RRT-Connect 快速首解，RRT* 花时间优化；
2. **一次查询和多次查询不同**：树通常服务单次问题，PRM 可摊销路网成本；
3. **随机算法有分布而非单值**：一次成功/失败或一次耗时不能代表性能；
4. **场景结构不同**：开放空间、狭窄通道、重复工位、双臂 14 维约束需要不同策略；
5. **可以做 fallback/并行候选**：MoveIt 支持多 pipeline 后按任务要求选择结果；
6. **便于识别真正瓶颈**：换 planner 完全无改善时，问题可能在 IK、碰撞模型或约束，而非
   搜索算法。

## 12. 可复现实验

运行教学对比：

```bash
ros2 run manipulation_core planner_comparison_demo
```

本轮固定二维圆障碍的一次输出为：

```text
RRT          solved=true work=25   waypoints=15 length=2.7332
RRT-Connect  solved=true work=29   waypoints=17 length=3.0223
RRT*         solved=true work=2500 waypoints=9  length=2.2327
PRM          solved=true work=221  waypoints=6  length=2.3456
```

这不是性能排行榜：RRT/RRT-Connect/RRT* 的 `work` 是迭代数，PRM 是 Dijkstra 展开数；固定
种子的单次结果也没有方差信息。它只能证明算法机制和“更久优化可能得到更短路”这一具体
样本。正式比较至少应执行 100 个种子，统计成功率、规划时间中位数/P95、首次解时间、最终
路径代价、碰撞检查数和内存。
