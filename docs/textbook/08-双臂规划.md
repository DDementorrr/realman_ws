# 第八章：双臂规划和协调执行

## 1. 双臂不是两个单臂 launch 的简单相加

两台 7 轴机械臂共同工作时，完整关节状态有 14 维：

$$
\mathbf{q}
=
\begin{bmatrix}
\mathbf{q}_{L}\\
\mathbf{q}_{R}
\end{bmatrix}
$$

$\mathbf{q}_{L}$ 是左臂的 7 个关节，$\mathbf{q}_{R}$ 是右臂的 7 个关节。双臂至少有三类任务：

1. 独立任务：两臂无耦合，各自规划；
2. 同步但不刚性耦合：规定到达时间或阶段一致；
3. 协同搬运：两端夹持同一刚体，相对位姿必须在全路径保持不变。

当前实现完成前两类的接口骨架：`both_arms` 一次碰撞感知规划并同时向两控制器执行。尚未
实现物体闭链约束、抓取力分配和真实 Duo 硬实时同步，不能把它称为完整协同搬运系统。

## 2. SRDF 规划组

项目 SRDF 定义：

```text
left_arm:  left link0 -> left link8
right_arm: right link0 -> right link8
both_arms: subgroup(left_arm) + subgroup(right_arm)
```

每个单臂组配置 KDL IK。复合组没有单个 IK solver；协调适配器分别给两个 tip 添加 pose
target，MoveIt 在同一个 PlanningScene 和 14 维状态中求解、规划。

已知同一臂相邻/永不接触 link 可在 SRDF 中禁碰；左右臂之间默认保留碰撞检测。随意生成
大范围 disable-collision matrix 会掩盖双臂互撞。

## 3. 固定 Duo 几何

模型来自 `franka_description` 2.9.0 的 `fr3_duo_mount_v0_3`：左右安装点 y 为
`+/-0.05018 m`，且分别具有镜像 roll/yaw 和相同 pitch。不要自行用“左右各平移半米”的
临时安装矩阵代替官方支架；基座变换会改变两臂工作空间重叠区和碰撞关系。

## 4. 协调目标适配器

`dual_target_pose_executor.cpp` 的状态机：

1. 独立接收并缓存 left/right PoseStamped；
2. 服务调用时原子地复制两个目标，避免一半是新值、一半是旧值；
3. `setStartStateToCurrentState()` 使用最新仿真反馈；
4. 在 `both_arms` 上给两个 tip 同时设置目标；
5. 一次 plan；
6. 一次 execute，MoveIt 按关节拆给左右控制器；
7. 任一控制器失败则整体执行失败。

`busy` 防止服务请求重入。进一步工程化应给目标加 request ID、时间戳一致性和显式 action
接口，以便反馈、抢占和超时。

## 5. 刚性物体闭链约束

若两夹具抓住同一物体，理想约束为：

$$
\left({}^{\mathrm{world}}\mathbf{T}_{\mathrm{left\_tcp}}(\mathbf{q}_L)\right)^{-1}
{}^{\mathrm{world}}\mathbf{T}_{\mathrm{right\_tcp}}(\mathbf{q}_R)
=
\mathbf{T}_{\mathrm{relative}}^{\star}
$$

左侧先把左右 TCP 都放到同一个 world 坐标系，再计算“右 TCP 相对于左 TCP”的位姿；
$\mathbf{T}_{\mathrm{relative}}^{\star}$ 是抓住刚体后希望始终保持的目标相对位姿。

可定义六维相对位姿误差：

$$
\mathbf{e}_{\mathrm{relative}}
=
\operatorname{Log}\!\left[
\left(\mathbf{T}_{\mathrm{relative}}^{\star}\right)^{-1}
\mathbf{T}_{\mathrm{relative}}(\mathbf{q})
\right]
$$

$\operatorname{Log}$ 在这里把一个刚体位姿差转换成便于优化的六维误差向量。理想保持约束时，
其一阶速度关系近似为：

$$
\mathbf{J}_{\mathrm{relative}}(\mathbf{q})\dot{\mathbf{q}}=\mathbf{0}
$$

意思是双臂可以运动，但这种联合运动不能改变两个夹具之间的相对位姿。

采样式规划需要约束流形投影或专用 constrained planning。还要把物体 attach 到规划场景、
检查物体碰撞，并计算两臂力/内力分配。当前普通两个 pose endpoint 约束只保证终点，不保证
中间相对位姿恒定。

## 6. 维数和性能

14 维均匀采样比 7 维困难。可利用任务结构：

- 无耦合时分别规划再做时序碰撞协调；
- 共同物体时在约束流形采样；
- 给良好 seed/goal state，限制无关自由度；
- 对场景使用合理碰撞几何；
- 用 experience/roadmap 或任务与运动规划分层。

## 7. 仿真和实机合同不同

当前 Gazebo Duo：两个 JointTrajectoryController 使用 position command interface，适合验证
MoveIt 的关节拆分和视觉同步。

官方固定 FR3 Duo 实机 bringup：当前公开支持的双臂 command path 是 effort/torque。要迁移
实机，需要新建 Franka hardware adapter/effort controller，不能复用 Gazebo position
controller YAML 宣称兼容。官方 mobile FR3 Duo MoveIt 配置包含 left/right/mobile/full_body
组，可作为更完整系统参考，但本工程此阶段选固定支架以隔离移动底盘变量。
