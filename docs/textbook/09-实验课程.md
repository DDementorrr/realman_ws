# 第九章：循序实验与验收题

每个实验都应记录：代码/模型版本、命令、输入、预期、实际输出、判定和遗留风险。

## 实验 1：2R FK 手算对照

1. 手算 $\mathbf{q}=[\pi/4,-\pi/2]^{\mathsf{T}}$ 时的 $x$、$y$；
2. 运行 `ros2 run manipulation_core kinematics_demo`；
3. 误差应在浮点容差内；
4. 修改一行 DH 的 $\alpha$，解释末端如何离开平面。

## 实验 2：Jacobian 有限差分

对每个关节用 $\varepsilon=10^{-7}$ 扰动，比较 FK 平移差分和 `geometricJacobian()` 上三行。
随后在伸直 2R 位姿计算奇异值，解释丢失的运动方向。

## 实验 3：DLS IK

从三种不同 seed 求同一目标，记录迭代数、误差和解；把阻尼 $\lambda$ 从 $10^{-4}$ 改到
$10^{-1}$，比较奇异附近行为。测试不可达目标必须返回 `converged=false`，不能输出 NaN。

## 实验 4：四种采样规划器绕障碍

运行：

```bash
ros2 run manipulation_core planner_comparison_demo
```

使用二维圆形禁区 CollisionChecker。证明 start 和 goal 有效、直线无效、四种规划器路径
所有边有效。然后修改随机种子并统计 100 次成功率、首次解时间、总时间、路径长度和碰撞
检查数。PRM 需要把建图时间与查询时间分开；RRT* 要把首次解和最终解分开。

## 实验 5：五次时间缩放

检查首尾 $\mathbf{q}$、$\dot{\mathbf{q}}$、$\ddot{\mathbf{q}}$；把 duration 加倍，验证最大
速度约减半、最大加速度约变四分之一。再故意选取过短的总时长 $T$，使速度或加速度超限，
写出程序应怎样自动放大时长。

## 实验 6：FR3 单臂仿真


终端 B：

```bash

  "{header: {frame_id: base}, pose: {position: {x: 0.34, y: 0.0, z: 0.48}, orientation: {w: 1.0}}}"
```

目标是否可达与姿态有关；教学时建议先用 `tf2_echo` 读取当前 link8 位姿，再只平移 2 cm。
验收以 controller `Goal reached` 和 MoveIt `SUCCEEDED` 为准。

## 实验 8：FR3 Duo 协调轨迹

先发布：

```text
/manipulation/dual/left_target_pose
/manipulation/dual/right_target_pose
```

再执行：

```bash
ros2 service call /manipulation/dual/plan_execute std_srvs/srv/Trigger '{}'
```

日志应显示同一次执行向左右 controller 各发送一段轨迹并都成功。也可运行：

```bash
ros2 run manipulation_demo interactive_dual_target
```

## 实验 9：故障注入

将一个 MoveIt controller action namespace 临时改错，观察“规划成功、执行失败”。恢复后把
一个 controller 保持 inactive，比较错误。实验完成必须恢复文件，报告中记录差异。

## 实验 10：模型交叉校验

从官方 FR3 Craig-DH 和 URDF 分别计算同一 $\mathbf{q}$ 的 link8 pose。只有在
base/tool/frame 约定一致后才比较。要求记录平移范数误差和旋转角误差；若不一致，逐级比较
${}^{0}\mathbf{T}_{i}$ 定位第一处
分歧。

## 实验 11：MoveIt 多 planner 公平比较

保持 FR3 的 start/goal、PlanningScene、超时和速度缩放完全相同，分别启动：

```bash
ros2 launch manipulation_bringup franka_moveit_gz.launch.py \
  variant:=fr3 planner_id:=RRTConnectkConfigDefault
```

依次替换为 `RRTkConfigDefault`、`RRTstarkConfigDefault`、`PRMkConfigDefault`、
`PRMstarkConfigDefault`、`LazyPRMstarkConfigDefault`、`KPIECEkConfigDefault`。每个 planner
至少运行 30 次。若 Plan 成功而 Execute 失败，把它归入执行链错误，不能计作 planner 失败。

## 实验 12：教学实现和 OMPL 的差分测试

选取可直接表达成关节向量与简单障碍的小问题，在教学 planner 与 OMPL 中使用相同限位、
起终点和离散碰撞分辨率。不要求路径节点完全相同，而验证：两者都不越界、逐边有效、成功率
统计合理。记录教学实现缺少的状态空间、约束和路径处理能力。

## 完成本教材后的核心能力清单

- 能解释 URDF 与 DH 为何不能直接逐字段互抄；
- 能手推 FK/Jacobian/DLS 更新式并在代码中找到每一项；
- 能区分 IK、路径规划、时间参数化和反馈控制；
- 能沿 action/controller/joint-name 链诊断执行失败；
- 能说明 7 轴冗余、双臂 14 维状态和闭链约束；
- 能判断一份模型是否足以做动力学，而不把仅含 mesh 的 URDF 当精确质量模型；
- 能清楚区分 Gazebo position 合同与 FR3 Duo 实机 effort 合同。
- 能解释 OMPL 是算法库而 RRT 是算法，并能为单次、多次、最优和工业直线任务选择起始方案；
- 能说明智能体生成的教学实现为何不能仅凭单元测试替代成熟库。
