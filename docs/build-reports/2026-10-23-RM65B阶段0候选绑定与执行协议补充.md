## 结论

阶段 0 继续停留在 G0-6。本次为 backend-neutral 执行协议增加不可变候选绑定合同和离线拒绝测试，并让 MTC/仿真入口传递和校验场景 revision；不连接 RM65B 实机、不启动 Gazebo 执行、不提交或推送。MTC 尚未生成对象快照、场景摘要、任务配置摘要和起点状态摘要，现有仿真执行器尚未接入 `ExecutionCoordinator`，因此本次不代表候选协议已进入完整任务流程，G0-6 仍未通过。

## 变更

- `pick_place_runtime.CandidateBinding` 保存非负 scene revision、规范排序的对象 ID 集合，以及 PlanningScene、任务/模型配置、规划起点状态的 SHA-256 摘要。值对象不可变；ID 必须非空、唯一、无前后空白和控制字符；摘要必须是 64 位小写十六进制。
- `ExecutionCoordinator.start()` 增加可选绑定检查。在调用后端之前逐项校验当前 ready、revision、对象 ID 集合及三个摘要；缺字段、非法摘要或任一状态已变化都会拒绝执行。旧 `candidate_revision` / `current_revision` 调用形式保留。
- 原有后端注入、逐段成功确认、失败停止、超时取消及取消未确认进入 `BLOCKED` 的状态机逻辑保留。

此处摘要由调用方提供，本包不负责把 ROS/MTC/机器人状态序列化成规范快照，也不声称 revision 本身等于场景哈希。摘要规范化和采集时间/一致性须由未来的 ROS 适配层落实。

## 场景 revision 接入

- MTC 在等待外部 PlanningScene 时订阅 `/perception/scene_revision` 与 `/perception/scene_ready`；若 SceneSync 流已出现但尚未 ready，规划不会开始。成功候选发布时，通过 transient-local `/pick_place/candidate_scene_revision` 发布规划时的 revision。
- 仿真执行器订阅候选 revision 和当前 SceneSync revision/ready。场景变化或 ready 撤销后，旧候选无法触发执行；没有 SceneSync revision 的旧 known-scene 入口保留明确的 legacy 兼容模式。
- 当前发布的 revision 只是候选绑定的版本门控，不是完整 `CandidateBinding`：对象集合、场景/任务配置和起点状态摘要仍待 ROS/MTC 适配层生成。
