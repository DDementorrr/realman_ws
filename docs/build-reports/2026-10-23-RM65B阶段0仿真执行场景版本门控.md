# 2026-10-23 RM65B 阶段 0 仿真执行场景版本门控

## 结论

阶段 0 继续停留在 G0-6。本次将 SceneSync 的 `/perception/scene_revision` 和 `/perception/scene_ready` 接入现有 Gazebo 仿真执行入口的执行前门控：候选收到时记录当前 revision，触发执行前必须仍处于同一已确认 revision；场景变化或撤销 ready 会拒绝旧候选。未启动 Gazebo 任务、不连接实机、不提交或推送。

## 实现范围

- 版本判断纯函数放入无 ROS 的 `pick_place_runtime.scene_revision_status`，覆盖 revision 流未出现时的兼容模式、候选无 revision、场景未就绪和 revision 不一致。
- `pick_place_sim/execute_pick_place.py` 订阅 `/perception/scene_revision` 与 `/perception/scene_ready`。收到 MTC solution 时记录当前 revision；后续 revision 改变或 ready 变为 false 时，`/pick_place/execute` 和自动执行都拒绝启动，并返回明确原因。
- 现有 known-scene 入口不发布 SceneSync revision，因此保留 `scene_revision_unavailable_legacy_mode`，不破坏已存在的已知位姿仿真接口。带场景管理的视觉入口可使用严格门控。
- `pick_place_sim` 增加对 `pick_place_runtime` 的运行依赖；公共 runtime 仍不依赖 ROS、Gazebo、MoveIt 或厂商 SDK。
