# 2026-09-22 RM65B 与 CTM2F110 目录重组及 ROS 2 SDK 构建报告

## 目标

按机器人对象拆分 `src/`，让 RM65B、CTM2F110 夹爪和通用 ROS 2 适配层各自形成清晰边界；同时把知行官方 ROS 1 SDK 作为可追溯的本地 SDK 快照封装为 Ubuntu 22.04 / ROS 2 Humble 可构建的实机接口包。

## 目录结构

```text
src/
├── realman_rm65/
│   ├── rm_description -> ../../upstream/realman_ros2/rm_description

```

ROS 2 包名保持不变，只有源码目录分组改变；`rm_description` 仍指向固定的 RealMan 上游提交，官方源码未复制或修改。

## CTM2F110 ROS 2 SDK

`changingtek_gripper_driver` 包含 `vendor/ctm2f110_sdk`，随包供应官方 `CRTServo` 库、头文件、许可证和 `gripper.cpp/.h`。头文件及架构库与 ROS1 归档逐字节一致；`gripper.cpp/.h` 是包内适配副本：`setpos` 增加写入 ACK 结果返回，另增加 `readpos` 读回封装。ROS 2 包提供 `FollowJointTrajectory` action、六关节 `/joint_states`、串口参数和归档使用的位置换算 `servo = 1700 - 700 * q`。因此它不是未修改的官方 ROS 2 SDK，而是官方串口 SDK 的 ROS 2 驱动包装与少量接口扩展。

来源快照为 `upstream/changingtek` 提交 `dd27be09df77be843c15a1133b0e11130b31a7b2`；供应文件和动态库已复制到包内，
因此构建、安装和后续工作空间迁移不依赖上游目录仍然存在。x86_64 与 arm64 动态库 SHA-256 分别为
`7ecbb251b73537b4fbccabe98a5b89a5656eb71f1a15e63a54be1ff2b8d0de6b` 和
`39797e7e672549e69e6de2e29062bee1a59657e87efee33c4473c4d378115d48`。

默认 `dry_run=true`，不会打开串口。实机调试前需确认串口、权限、型号和停止流程，再显式设置 `dry_run:=false`；不能与 Gazebo 控制器或第二个 `/joint_states` 发布器同时运行。

验收范围包括：嵌套目录下的 8 个 ROS 2 包被 colcon 发现；RM65B + CTM2F110 xacro 可展开；SDK dry-run 节点可发布六关节状态并接受 `FollowJointTrajectory`；官方 SDK 未进入 ROS 1 Catkin 构建链。

## 本次复核结果

在已构建环境中运行了：

```bash
python3 scripts/verify_migration_manifest.py
bash scripts/verify_environment.sh
bash scripts/verify_realman_gz_runtime.sh
python3 scripts/verify_realman_gripper_gz_runtime.py --timeout 15
```

结果全部通过：Humble、Gazebo Sim 8（Harmonic）、MoveIt、`gz_ros2_control` 和 8 个工作空间包均可发现；
RM65B 与 CTM2F110 两个控制器为 `active`，MoveIt 及两个 `FollowJointTrajectory` action 可见，
夹爪主动关节值为 `0.30000 rad`，五个 mimic 关节与预期符号关系一致。

在最新驱动构建后再次执行 `0.65 rad` dry-run action 返回 `SUCCEEDED`，越限 `1.2 rad` 目标被拒绝。

另外，`FollowJointTrajectory` dry-run action 已验证 `0.65 rad`、`0.2 s` 轨迹点会按时间完成并返回
`SUCCEEDED`；驱动会拒绝越限、非单关节、时间倒序和并发目标，并接受取消请求。SDK 供应库的写入失败
会使 action 返回失败，而不是继续报告成功。

当前版本还以 Python action client 验证了 3 秒目标在约 0.2 秒后取消时返回 action 状态 `CANCELED`。

本次启动会话在人工发送 Ctrl-C 关停时，`move_group` 进程出现退出码 `-11`，同时 Gazebo 进程按信号退出。
该现象发生在验收完成后的关停阶段，不影响上述运行期间的控制器/action/关节状态检查；后续若需要长期运行，
应单独追踪 Humble MoveIt 退出路径，不能将其标记为已解决。

## 边界

当前未连接实机，因此不宣称串口打开、协议读回、负载、限位、急停或实机运动已经验收。SDK 二进制库来自官方 x86_64/arm64 快照；其他型号必须先做型号和协议核对。ROS 2 驱动已封装官方 `FeedBack`/`ReadPos(-1)` 读回路径，但必须在实际 CTM2F110E 上核对 ID、零位、串口波特率和读回单位后才可进入实机验收。
