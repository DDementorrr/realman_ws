# 瑞尔曼 RM65B 联合仿真构建报告

日期：2026-09-11。

## 目标与来源

目标是在现有 ROS 2 Jazzy、MoveIt 2 和 Gazebo Harmonic 工程中增加 RM65B 标准版裸臂的
RViz 交互规划、Gazebo 执行和参数化目标入口。系统 PDF 只用于识别本体、主控环境与夹爪，
没有将其中叙述当成构建指令。

厂家仓库 `humble` 分支固定到提交
`c941b565e4f9174afa36561f143ef5fbbb744750`，位置为
`manipulation_ws/upstream/realman_ros2`。厂家公开说明的运行基线是 Ubuntu 22.04 与
ROS 2 Humble，因此未将其驱动、旧启动文件和全部示例加入 Jazzy 默认构建。

## 工程变更

- `src/realman_rm65/rm_description`：指向固定厂家 `rm_description` 的构建符号链接，源码保持干净；
- `scripts/prepare_realman_model_source.sh`：在全新导入后安全重建上述链接，不覆盖已有路径；
- `robot_realman_moveit_config`：项目维护的 SRDF、KDL、OMPL、关节限位、控制器映射和 RViz；
- `robot_gazebo`：新增 RM65B 的 Harmonic description 和 controller YAML；
- `manipulation_bringup`：新增按 paused、configure、unpause、activate、MoveIt/RViz 顺序门控的启动；
- `manipulation_moveit_adapter`：复用现有目标位姿执行器；
- `scripts/verify_realman_gz_runtime.sh`：运行时只读验收；
- `upstream.repos`、IDE 分类、AGENTS.md 和工程纲领已同步。

规划模型发布到 `/robot_description`；包含 `gz_ros2_control/GazeboSimSystem` 的仿真描述独立
发布到 `/robot_description_gazebo`。执行状态只来自 Gazebo `/joint_states`。

## 构建结果

以下目标及其依赖构建成功，共完成 10 个包：

```bash
colcon build --symlink-install --packages-up-to \
  manipulation_bringup robot_realman_moveit_config robot_gazebo rm_description
```

规划 URDF 与 Gazebo URDF 均通过 `check_urdf`，机器人链分别以 `base_link` 和 `world` 为根，
并包含 Link1 至 Link6。启动参数能够由 ROS 2 launch 解析。

`rosdep check --from-paths src --ignore-src` 报告系统依赖满足；三个项目适配包的 colcon test
完成。架构检查确认三个 upstream 仓库的本地提交、官方 origin 与干净状态。远程
`vcs validate` 长时间没有返回，已人工中止，未将网络等待误判为源码缺失。

主机没有 `pdftotext`，安装系统包需要交互式 sudo，因而没有改变系统环境；本轮仅在 `/tmp`
隔离虚拟环境中临时使用 pypdf 读取 7 页系统说明，不把该工具列为工程运行依赖。

## 未纳入范围

- 没有编译或启动厂家 `rm_driver`，没有连接实机；
- CTM2F110E 夹爪和深度相机尚未建模；
- 没有把厂家 ROS URDF 的惯量视为经实机辨识的动力学参数；
- 没有验证移动底盘、双机网络或 Ubuntu 22.04/Humble 实机主控部署。
