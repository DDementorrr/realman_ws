## 实现

- `pick_place_scene/scene_sync.py` 用 `ROBOT_STATE_ATTACHED_OBJECTS` 查询附着状态，拒绝附着对象的世界观测写入。发送 apply 前重新检查观测年龄。
- 查询、apply 和确认各有 `service_timeout_sec`，默认 5 s；watchdog 使用 steady clock，仿真时钟暂停不影响超时。每个对象的事务身份和阶段隔离迟到回调，清除本地 pending request 不表示远端已取消。
- 无副作用查询超时可重试；apply 已发出后发生超时、异常、拒绝或回查不匹配时，将该对象锁定到节点重启，明确报告结果不确定，避免自动重复写入。其他对象仍可处理。
- 观测接受单个 BOX ADD 或稳定 ID 的 REMOVE。ADD 检查 ID、frame、有限正尺寸、单位四元数、非零且不过期/非未来的时间戳；REMOVE 不要求几何体，但仍检查 ID、frame 和新鲜时间戳。两者均拒绝额外 mesh/plane/subframe 和非 identity 顶层观测变换；兼容现有生产端的默认全零顶层 pose。
- REMOVE 与 ADD 共用查询、应用和回查事务：删除必须确认目标不存在才递增 revision；应用失败或删除后仍存在会锁定对象，附着对象的删除仍被拒绝并保留已确认状态。
- 回查比较 ID、frame、尺寸与组合后的实际位姿，容差 `1e-6`（位置/尺寸为 m，四元数为无量纲），允许四元数正负等价。实际 MoveIt 会将 primitive 位姿规范化到顶层 pose，使用 `tf2_geometry_msgs` 组合变换后比较。首次真实探针暴露了字段直接比较的误拒绝，修正后复验通过。
- PlanningScene diff 同时设置 `scene.is_diff` 和 `scene.robot_state.is_diff`，避免更新环境时替换附着状态。新包补齐 `launch`、`launch_ros` 及各自直接消息/TF 依赖。

这仍不是完整的场景版本和任务协议：外部 attach 写入者与 query/apply 之间存在竞争窗口，`confirmed_ids` 仅为内部诊断，不是持续有效的公共 ready 状态；尚无统一写入所有权、attach/detach 协调、候选失效或执行取消联动。ADD/REMOVE 已有公共事务验证，但确认只接受同一 frame，未实现跨 frame 等价比较。
