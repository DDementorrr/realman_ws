- `scripts/verify_candidate_revision_contract.py`：检查 MTC 对 `/perception/scene_revision` 与 `/perception/scene_ready` 的订阅、候选 revision publisher、规划成功及选中解后的发布顺序、revision 快照和 ready 条件。

对候选脚本的人工审阅发现两条容易漏检的路径，已在源仓库 verifier 中加强：候选发布移入 `!selected` 失败分支，或执行器将 `scene_ok` 放入可被 OR 绕过的条件。临时副本变异检查结果如下：

| 情况 | 结果 |
|---|---|
| 原始代码 | 通过，退出码 0 |
| MTC 候选发布移入无选中解的错误分支 | 拒绝，报告发布必须位于失败 guard 之后 |
| `ready()` 顶层改为 OR | 拒绝，要求正向 conjunction |
| 将 `scene_ok` 放入嵌套 OR | 拒绝，要求 `scene_ok` 是直接正向条件 |

worker 的变异检查还覆盖删除执行门控、订阅、manifest 依赖、破坏 legacy helper 行为及将发布移至规划之前；均被拒绝。最终新增脚本独立运行通过，`py_compile` 通过。worker 固定检查中的执行协议、revision 门控、MTC 隔离、migration manifest、环境和 whitespace 检查通过；应用后在源仓库重跑候选检查、migration、11 项执行协议、5 项 revision 门控、MTC 隔离、Humble/Harmonic 环境检查和 `git diff --check` 均通过；从 `/tmp` 调用 shell 入口也正确定位仓库并通过。
