## 实现边界

- `pick_place_mtc`：不同配置逐个构造完整 MTC Task；规划完成后保持 Task 地址和 introspection 生命周期稳定。源包括 front、left、right、夹爪 spin、预抓取距离、运输 waypoint、不同 place/retreat 方向、RRTConnect/RRT 和重复规划预算。旧 `planning_candidates` 仍是每个配置内的多解数量，不当作新多样性。
- Approach、Lift、Place、Retreat 仍是 Cartesian；运输和 waypoint 为 OMPL。不存在虚构的逐请求随机种子：本安装的 PipelinePlanner 没有暴露该接口，`rng_seed: null` 并记录未控制进程 RNG，场景种子与规划 RNG 分开。
- `candidate_audit.hpp` 遍历实际 MTC 叶子轨迹及对应阶段 PlanningScene，检查完整阶段、关节位置、命令与有限差分速度/加速度、时间参数化、零时间内部跳变、整机自碰撞和环境碰撞、环境最小间隙。使用该阶段原有 ACM，只豁免既有预期抓取/支撑接触。末端相机补上与原 visual 等大的碰撞盒；有 visual 而无 collision 的模型被拒绝。
- 轨迹组之外的关节按前一实际已执行位置拼接，不直接采用各分段 RobotState 中非运动组的缓存值；附着对象从该阶段 scene 继承。这是完整夹爪/载荷碰撞检查所必需。
- 碰撞重采样的最大单关节增量为 0.01 rad，默认环境间隙硬门槛 1 mm。边界的 IK 数值一致性容差显式为 0.001 rad；实际样本约 0.0001 rad。起点与 fresh `/joint_states` 的 raw delta 要求 0.01 rad 内，ROS/steady 年龄不超过 1 s，明显未来时间戳拒绝。以上均为离散仿真检查，不是连续碰撞、硬件制动或实机误差认证。
- 硬约束通过后才评分，越界不能被低代价抵消，精确同分保留首次候选。相机和夹爪均在公共碰撞模型中参与检查；无新增仿真依赖进入公共包。

## 生产者与真实消费者

复用 `/pick_place/solution`、`/pick_place/task_description`、`/pick_place/planning_metrics`、`/pick_place/candidate_scene_revision`，没有新增自定义消息、复制 revision 或静默重规划服务。

`planning_metrics` 仍为 String，内容升级为 `pick_place_candidates/v1` 结构化 YAML，同时原子保存一次运行归档。记录候选 ID、目标/放置、场景、起点、模型/参数、外部碰撞资源/标定配置摘要、全部候选的代价/间隙/拒绝原因及实际多样性。解和 description 的 CDR 原文用于无歧义绑定；消费者反序列化后比较消息语义，不假定两次序列化的 padding 字节相同。

规划前冻结一个真实 PlanningScene 和实际反馈起点；规划结束再次检查场景几何、ACM、固定 TF、附着、padding/scale、模型/配置、源文件和 fresh 反馈。跨场景/模型变化不发布就绪。Task 在求解后不再搬移，避免 introspection 的 stage 注册引用失效。

执行器实际消费该归档：拒绝未绑定/旧式纯文本指标、被替换的解/description、改变的规划/模型参数、实际场景（即使 revision 不变）、文件摘要、目标/放置、过期或变化的反馈。RGB-D 模式还核对实际感知节点参数与当前 collision-model hash。固定相机显式启用 `monitor_fixed_calibration`，完整 CameraInfo 与采集时刻外参改变即撤销输入有效。动态腕部相机不被这个固定相机出口批准。

无 ROS 的 `pick_place_runtime` 状态机/租约库保持无 ROS 依赖；ROS 消息绑定 helper 随 `pick_place_mtc` 安装，真实执行编排仍在 sim。保持 3 s 感知租约、150 ms 完整束跨度、80% 深度阈值、全未知保护和每侧 35 mm 膨胀。

## 失败迭代与限制

最终 RGB-D 复核中保留了三次真实失败：domain 183 的首个 verifier 对 Humble 的 `DiagnosticStatus.level` 字节字段处理错误；第二次执行前校验占住默认互斥回调组，使 `/clock` 和关节反馈未及时消费，执行器按 1 s 门槛拒绝；第三次实际完成接近、闭爪和附着，搬运时监测报告新增占用/未知，真实取消确认并故障锁存。均未记为通过。

长耗时 `/pick_place/execute` 校验和自动触发改用既有 ReentrantCallbackGroup，反馈与时钟回调持续运行；没有增大反馈新鲜度门槛。生产 ROS 服务并发回归使用真实归档、受控外部校验/场景替身，证明 1.4 s 校验期间 0.5 s 心跳、时钟和关节仍更新，并证明校验期间取消不会派发动作或激活任务租约。这是 ROS 并发回归，不是 Gazebo 运动证据。

第三次停机后录制五路实际 RGB-D 并复算，确认部分“新占用”是网格边界重栅格化误差：已生成的体素盒经减法/除法后落到整数前后一 ULP，`floor/ceil` 再扩出整层 1 cm 单元。现在仅在 16 倍浮点 eps 的算术误差范围内吸附整数边界，真实离格边界仍严格向外取整；没有减少原始未知、35 mm 膨胀或深度误差。增加实际工作区坐标往返和 0.1 nm 离格扩展回归。`stop183-independent-grid-fix.json` 对原停机录包复算：新增正占用 0，573 个新增未知全部有实际已知表面见证，五路生产与逐像素/全三角形参考一致，原始未知未改变。该停机录包不是完整运动证明，仍需新 fixture 的整任务复测。

domain 184 在网格修正后有 7 条硬有效完整候选，选择 yaw_front；实际接近和闭爪成功，247 条动作区间诊断全部 OK、确认帧 122→134，但 Gazebo 动态加载附着插件后丢失首次 attached 回执，4 s 未确认而锁存失败。停机后仅对本轮 Gazebo 发 detach 得到真实 detached 状态，证实插件此前已附着；没有清除锁存或重执行旧候选。适配器现在在首次加载时先等待真实 attached 回执，若首次事件丢失，则在静止首次抓取边界要求新的 detached 回执，再请求并确认 attached；不会根据 system/add 成功或旧本地 detached 字符串推断成功。无回执仍失败关闭，没有增加通用故障恢复服务。

domain 185 在候选生成期间感知 3 s 租约过期；规划器保留部分归档并拒绝发布，未派发动作，最终完整任务不计通过。排查发现本地公共 C++ 包此前以空 `CMAKE_BUILD_TYPE` 编译，密集全任务审核与五路感知争用 CPU。后续运行显式采用 `RelWithDebInfo` 优化构建并重新验证原生硬门槛；不放宽租约、采样步长或间隙，也不沿用该失效场景。

早期失败日志保留：Humble kinematics 插件声明了未初始化可选数组，导出参数时现在明确记录并跳过其无值项；未替换真实参数。最初 checker 对非运动组缓存和 IK 微小数值残差的处理不正确，已修正并记录显式容差。一次求解后搬移 Task 使 introspection 报 unregistered stage，已改为 init/plan 后保持地址不变；不得以关闭诊断掩盖错误。

原生 checker 测试曾缺少完整 include；第一次 fixture 节点名与 name-scoped 参数不符，另一次位置/速度错误类别混淆；均保留失败日志并在同源代码修复、重跑。原 Task 析构晚于 ROS shutdown 的测试清理警告已调整资源生命周期。
