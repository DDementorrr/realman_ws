# 2026-10-24 RM65B 阶段 3 静态 Gazebo 真值同步与旧解拒绝验收

## 范围与实现

本轮承接扩展方案阶段 2，建设阶段 3 的静态真值输入、增删回查及旧解拒绝。未调用 cheap-worker/低价模型，未连接实机。动态运行时多障碍同步、执行中环境变化的所有权及取消故障注入仍需专项验收，不在本静态增量中宣称完成。

- 仿真包 `pick_place_sim/pick_place_sim/gazebo_geometry.py` 调用 Harmonic 的 `/world/empty/generate_world_sdf`，读取**实际运行 world**，提取已配置障碍物的实际 model 名称、位姿以及 visual/collision 尺寸。仅完整成功导出中缺失的实体才生成 REMOVE，超时、错误 world、坏 XML、非 Box、局部几何偏移、重复实体或 visual/collision 不一致均失败，不回退为 YAML 位置，不把读取失败当成障碍物消失。
- `pick_place_sim/scripts/gazebo_obstacle_state_sync.py` 发布标准 `moveit_msgs/CollisionObject` 到 `/perception/collision_objects`，发布 `diagnostic_msgs/DiagnosticArray` 到 `/perception/obstacle_status`。它只有只读 GetPlanningScene 客户端，不直接调用 ApplyPlanningScene。公共 SceneSync 仍唯一写环境。
- 中性快照继续提供稳定障碍物 ID 白名单、安装变换和初始 Gazebo world；工作台三段保持冻结，障碍物位置/尺寸只从 live SDF 提取，再由显式 world→base 平移转换。暂仅支持当前无旋转固定安装及单 link 静态 Box。
- 公共 SceneSync 增加可选 `required_ids` 与标准 Bool `input_ready_topic`。两者默认关闭，原入口兼容。真值入口要求所有初始障碍物被确认，并由上游 `/obstacles/truth_ready` 表示一次完整导出已完成；读取或回查失败不就绪。无仿真依赖流入公共包。
- `obstacle_pick_place.launch.py` 新增 `obstacle_source:=snapshot/gazebo_truth`，默认仍为阶段 2 快照模式。真值模式把工作台与障碍物源分开，公共管理先加载 `support.yaml`，再接收真值观察；不产生第二个桌面或目标写入者。

保留既有 MTC、revision 候选绑定和执行后端。真值模式禁止 `auto_execute:=true`，只允许显式触发。`/obstacles/refresh_truth` 使用标准 Trigger 启动一次静态刷新，服务成功仅表示接受任务；诊断、真值就绪与公共场景回查才证明完成。开始刷新时先撤销上游就绪；每个差异 ID 只提交一次，随后只读回查，避免重复 REMOVE 或不变几何造成 revision 抖动。

本阶段的刷新限于尚未执行的静态场景。收到开始执行、完成或故障状态后拒绝再次刷新，需重启。此限制不是与外部控制器的原子所有权协议，用户也不得在刷新过程中并发触发执行。仿真实体变更需显式刷新；没有持续动态检测的安全承诺。删除初始必需障碍物后，缺 ID 会保持公共未就绪；重建同 ID 并确认后恢复就绪，但旧候选的 revision 仍然过期，不会被悄悄重规划或复用。

| 不变场景显式刷新 | 4 | 不写入、不增加 revision |

全程未发运动动作。检查全部已观察关节在测试前后差值不超过 0.005 rad，保持静止。verifier 为 `scripts/verify_stage3_truth.py`，只在明确的单薄墙 Gazebo 真值场景中使用，会变更测试障碍物并恢复；不能用于实机或正在执行的场景。

早期 `scene/` 发现轮询重复提交 REMOVE，MoveIt 对第二次删除返回失败，公共管理正确锁定未就绪。已修正为每次刷新每个差异 ID 只发一次并只读回查；锁定实例关闭，`scene-final/` 全新实例完成上述回归。保留原错误证据。两个 verifier 初期未等待全部异步保留话题到达，已补齐启动谓词；不以观察时序失败充当功能证据。

多对象补测 `scene-random/` 还发现既有公共观察订阅 depth=1 会丢弃一次突发发送的部分 ID；未确认对象使公共未就绪，没有提前放行。修正为每个查询周期只发一个差异 ID，不改公共订阅兼容设置，不新增批次接口。最终 domain 136 / partition `rm65b-stage3-multiple` 的 seed 42 独立启动，`scene-multiple/` 的全部 5 个障碍与 3 个工作台确认，通过实际 Gazebo/MoveIt 8 个 Box 一致性、初始机器人有效及完整 MTC 规划，结果见 `multiple-geometry.log`、`multiple-plan.log`。这是多对象静态串行确认，仍不构成动态原子快照。
