# 2026-09-23 RM65B 与 CTM2F110 目录及文档复核报告

## 复核目标

核对 `src/` 是否按对象与通用适配职责组织，确认夹爪 ROS 2 接口及随包 SDK 资产可构建，
并检查工程文档分类入口是否反映当前 RM65B + CTM2F110 主线。

## 目录边界

```text
src/
├── realman_rm65/
│   ├── rm_description -> ../../upstream/realman_ros2/rm_description
│   ├── robot_realman_moveit_config/
│   └── robot_gazebo/
├── crt_ctm2f110_gripper_visualization/
│   ├── robot_changingtek_description/
│   └── changingtek_gripper_driver/
│       └── vendor/ctm2f110_sdk/
└── ros2_adapters/
    ├── manipulation_bringup/
    ├── manipulation_moveit_adapter/
    ├── manipulation_demo/
    └── pick_place_demo/
```

ROS 包名保持不变，包目录按维护对象归组。`robot_gazebo` 和 MoveIt 配置仍在 RM65B 对象目录，
因为它们是该机型当前模型和运行组合的配套配置；跨对象的启动、请求适配与演示逻辑归入
`ros2_adapters/`。没有必要为了物理目录一一对应而拆分 ROS 包。

## CTM2F110 SDK 边界

`changingtek_gripper_driver/vendor/ctm2f110_sdk` 中包含 SDK 头文件、`gripper.cpp/.h`、许可证，
以及 x86_64 和 arm64 的 `libCRTServo.so`。头文件和架构库与 `upstream/changingtek` 归档一致；
`gripper.cpp/.h` 为适配副本，`setpos` 增加协议 ACK 成功/失败返回，`readpos` 增加双执行器读回。
ROS 1 归档中的其余串口协议实现没有改动。当前 ROS 2 包使用 `ament_cmake`，封装
`FollowJointTrajectory` action 与六关节状态发布；默认 `dry_run=true`。SDK 已随夹爪包安装，
不依赖 ignored 的上游归档目录。上游来源和二进制哈希记录见 2026-09-22 报告。

本次只验证 Ubuntu 22.04/Humble 下 x86_64 的构建和 SDK 动态库依赖。arm64 库已在源码包内，
但本机没有在 arm64 系统交叉或原生构建验收。未连接 CTM2F110E 实机，因此串口协议、型号兼容、
ID、波特率、位置换算、读回、运动和急停均不属于本次通过项。此包是 ROS 2 驱动封装，
不是 ROS 1 环境或 Catkin 节点。

## 构建和检查

在 `/home/ww/realman_ws` 执行：

```bash
source /opt/ros/humble/setup.bash
source .third_party/gz_ros2_control/install/setup.bash
colcon build --symlink-install
python3 scripts/verify_migration_manifest.py
bash scripts/verify_environment.sh
ldd src/crt_ctm2f110_gripper_visualization/changingtek_gripper_driver/vendor/ctm2f110_sdk/include/x86_64/libCRTServo.so
```

结果：9 个 ROS 2 包构建成功；两个 Python 包输出系统 `pkg_resources` 版本警告，不影响构建结果。
迁移 manifest 与 Humble/Harmonic 环境检查通过。已安装驱动的 `ldd` 依赖均可解析；设置
`dry_run=true`、`readback=false` 后节点成功启动并保持运行至 5 秒检查超时。该检查不打开串口，
不等于实机验收。构建与静态检查通过也不等于本次重新完成了 Gazebo/MoveIt 运行时回归。
