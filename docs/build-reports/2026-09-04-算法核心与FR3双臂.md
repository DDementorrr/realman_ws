## 新增与修改工程包

### manipulation_core

无 ROS/MoveIt/Gazebo 依赖的 C++17/Eigen 库：

- 标准 DH 和 Craig 修正 DH；
- FK、actuation frame、几何 Jacobian；
- 带关节限制/权重/步长限制的 DLS IK；
- CollisionChecker 抽象和双向 RRT-Connect；
- 五次时间缩放；
- 基于 COM Jacobian 的重力补偿；
- 带积分限幅的维数无关关节 PID；
- 2R 可手算 demo 与 gtest。

### robot_franka_moveit_config

- `fr3_arm` 单臂 KDL、limits、OMPL、controller mapping；
- 固定 Duo `left_arm`、`right_arm`、`both_arms`；
- 项目自有 Duo SRDF 避免上游配置的移动底盘/命名假设；
- 跨臂碰撞保持启用；
- FR3 与 Duo RViz 配置。

### robot_gazebo

- `fr3_gz.urdf.xacro` 与 `fr3_duo_gz.urdf.xacro`；
- 仿真专用 `/robot_description_gazebo`；
- ready position initial state；
- 单臂和双臂 JointTrajectoryController YAML；
- Gazebo position interface 明确只属于仿真合同。
- 将既有 PR2 adapter 同步加固为规划/仿真双描述、paused bringup、失败即终止门控，并补齐
  Gazebo mesh resource path；运行时左右臂、upper body 和 joint-state controller 均 active。

### adapters / demo / bringup

- 单臂 PoseStamped 即时 plan/execute；
- 左右独立目标；
- 双目标缓存 + Trigger 的 `both_arms` 协调 plan/execute；
- 终端实时输入工具；
- Gazebo paused -> spawn -> inactive controller load -> unpause -> activate ->
  MoveIt/RViz/adapters 的失败即终止门控。

## 已知边界

1. 教学算法未连接真实硬件，不能替代 MoveIt/厂家安全控制；
2. Duo 当前不含 gripper，因为官方固定 Duo bringup 未给出该路径，arms 是本里程碑范围；
3. 双臂 endpoint 协调已完成，闭链共同物体约束/力分配尚未完成；
4. Gazebo position controller 不能直接迁移到官方真实 Duo torque/effort 合同；
5. RViz trajectory display 在执行瞬间偶发模型未加载显示层错误，但执行链与状态同步正常；
6. 人工 Ctrl-C 时 Gazebo -2、move_group 超时 SIGTERM 是关停现象，不是运行期失败；bringup
   已注册 Gazebo server-control 关停处理，最终验收退出后复查无活动 Gazebo/ROS 节点。
