# 2026-09-04 规划算法教学核心扩展构建报告

## 目标

1. 澄清 `manipulation_core` 的代码来源和成熟库边界；
2. 将教学规划从单一 RRT-Connect 扩展为可对照的 RRT、RRT-Connect、RRT*、PRM；
3. 为 FR3/FR3 Duo 运行链开放多种成熟 OMPL planner；
4. 增加路径有效性、shortcut、算法选择和公平比较教材。

## 来源与依赖结论

教学包的算法体是依据公开算法定义重新编写的项目代码，没有复制或链接 OMPL/MoveIt
planner 实现。它使用 Eigen 做线性代数、GoogleTest 做测试、ament/CMake 做构建。

实际 FR3/FR3 Duo 规划继续通过 MoveIt 的 OMPL planner plugin；教学核心没有接到机器人
执行链。这一分离符合工程的 adapter 和安全边界。

本轮没有增加 apt、pip 或 rosdep 依赖。

## 代码变更

### manipulation_core

- `planning_utils.*`：离散边检查、整条路径检查、路径长度和随机 shortcut；
- `sampling_planners.*`：基础 RRT、带重连的教学 RRT*、可预建/复用路网的 PRM；
- `rrt_connect.cpp`：复用统一边检查；
- `planner_comparison_demo.cpp`：相同二维圆障碍下的确定性对照入口；
- 单元测试增加成功路径、逐边有效、PRM 路网复用、shortcut、碰撞端点拒绝和穿障检测。

### MoveIt adapter/config

- FR3 四个 planning group 均开放 7 个 OMPL planner；
- bringup 增加 `planner_id` 参数和 allow-list 校验；
- 单/双臂参数化 target adapter 均接收 `planner_id`；
- 默认保持 `RRTConnectkConfigDefault`。

## 已知边界

1. RRT* 是教学重连实现，只优化关节欧氏长度，不等同于 OMPL 完整优化框架；
2. PRM 使用线性近邻和 Dijkstra，适合教学小问题；
3. 边碰撞检查是离散插值，分辨率过粗仍可能漏过薄障碍；
4. 教学 planner 没有 RobotModel/PlanningScene/复杂约束/时间终止/近似解语义；
5. 单次固定 seed 输出只验证机制，不构成算法性能排名。
