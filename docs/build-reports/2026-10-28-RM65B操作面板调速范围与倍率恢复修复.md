# RM65B 操作面板调速范围与倍率恢复修复

日期：2026-10-28。范围：仿真 RViz 原生规划的前端限速请求；不更改模型额定速度、不连接实机。

## 限速来源与原问题

1. `robot_realman_moveit_config/config/rm65b_ctm2f110_joint_limits.yaml` 给出模型限速；裸臂使用 `rm65b_joint_limits.yaml`。本次加载模型的 joint1/2 为 3.141593 rad/s，joint3—6 为 3.926991 rad/s，前端关节请求不能超过这些值。
2. `rm65b.rviz` 的初始速度、加速度倍率均为 0.1。明确指定的原生倍率与 YAML 默认 0.15 不是再乘一次的关系。
3. 面板 TCP 默认 0.1 m/s，原本输入最大值已是 2 m/s。串联链下游长度和构造的保守几何速度系数约为 9.432633 m/s；默认 TCP 约束将共同倍率压至 0.010601，关节生效上限因此约为 0.033304/0.041630 rad/s。该系数是最坏情况估计，不是实际 TCP 速度或硬件能力。
4. 旧 `applyLimits()` 对“旧生效倍率”和“新上限”取最小值。提高 TCP 或关节上限后，旧的小倍率仍被保留，形成只降不升；用户还需要去原生控件再次提高倍率。

## 修改

- 新增简短的“规划倍率”输入，范围 0.000001—1；请求与生效值分开保存，不新增流程说明标签。
- TCP 输入保持 0—2 m/s，步长调为 0.05；0 显示“不限”，仅取消面板 TCP 平移约束，模型关节、关节请求和规划倍率仍有效。
- 点击“应用限速”，按当前独立请求和所有约束重新求生效倍率；提高约束允许速度恢复，降低约束仍立即使旧计划失效。
- 原生倍率控件明确为大于 0、至多 1；原生编辑同步到面板请求，生效值仍受约束。保留原生 Plan/Execute 与独立抓放接口。
- 遥测保留原字段，增加 `requested_velocity_scaling`、`maximum_velocity_scaling` 和 `tcp_limit_enabled`。
- README 与工作流说明补充取值、来源和应用顺序。加速度仍由原生 UI 配置；这不是最快时间参数化的实现。

## 验证与证据

证据目录为本机忽略目录 `log/operator-panel-speed-20261028/`。使用独立 ROS domain 92 与 Gazebo partition `rm65b_speed_20261028`，不操作用户已经运行的仿真。初步九项原生规划/低速执行探针已通过；新增倍率回归以 `final/` 结果为准。

`final/probe.json` 返回 `accepted: true`，共 15 项通过；重新构建当前探针后运行，确认包含新增的六项限速回归，而不只是原九项结果：

- TCP、关节与规划倍率控件取值范围和请求保留通过。
- TCP 上限从 0.1 提高至 0.5 m/s，生效倍率从 0.010601 提高至 0.053007，约五倍。
- joint1 请求降到 0.03 rad/s 时，实际生效上限不超过该值；恢复关节请求后倍率也恢复，不再锁在低速。
- TCP 设为“不限”且规划倍率设为 0.8 时，生效倍率为 0.8；模型与关节约束仍保留。
- 较高限值下只生成原生 Plan，逐点验证关节和 TCP 保守速度界；编辑和规划没有造成运动。
- 随后恢复 TCP 0.1 m/s 等低速设置，原生 Execute 的仿真 joint1 约 0.04 rad 动作到位；原生限速、旧计划失效、关节反馈、IK、物体坐标与标记同步回归通过。
- 回看最终面板截图，规划倍率、TCP 上限和生效倍率均清晰可见。没有改变用户当前仿真的限速或关节状态。

插件及配置两包构建、shell 语法、迁移清单、环境与 diff 检查通过。原生探针退出日志仍有既有 class_loader 对象未释放警告；不把本轮结果解释为退出生命周期问题已修复。所有动作仅发生在独立仿真。

## 使用

完整退出旧 RViz 并重新启动，编辑关节“请求上限”、TCP 上限和“规划倍率”，点击“应用限速”，再 Plan/Execute。修改不追溯更改正在执行的轨迹。面板限速只用于本 RViz 原生规划，不自动作用于独立 MTC、旧终端执行器或其他客户端。
