# 2026-09-18 知行夹爪 ROS2 资产与 RM65B 集成构建报告

## 目标与边界

把用户提供的 Gitee ROS1 资产导入当前系统，并建立 Jazzy 资产包、RM65B 末端装配、
Gazebo Harmonic 控制和 MoveIt 2 集成规划。只操作仿真；不构建、不启用 ROS1 串口脚本，
也不启用瑞尔曼实机驱动。

`git clone https://gitee.com/Ice_Panda/changingtek.git` 在本环境 90 秒超时，
`git ls-remote` 也未返回；Gitee 官方归档端点下载成功。导入的原始
`master.zip` SHA-256 为
`8535b4f70ea8292977f3666964405949de3db25c5e2835702436544f0dd70b00`。
因此本次有**归档字节锁定**，没有可核验的 Git commit pin。原 ROS1 目录在
`upstream/changingtek_ros1`，不参与 colcon，复现脚本只接受相同 SHA-256。
其 `LICENSE` 随适配包保留。Gitee 的 CTM2F110 包提供网格、同步/异步 Xacro、惯量和
ROS1 控制样例；没有独立的 CTM2F110E 包。

## 构建与静态检查

执行 `colcon build --packages-select robot_changingtek_description robot_realman_moveit_config
robot_gazebo manipulation_bringup --symlink-install`，四包成功。
组合规划 URDF、Gazebo URDF 均通过 `xacro` 展开和 `check_urdf` 树检查；Gazebo SDF 转换
保留主动关节与五个 mimic 声明。额外的项目架构、文档和环境检查结果见本报告末尾的
验收记录。

## 发现并处理的问题

1. 初始 DART 仿真中夹爪主动关节 action 可返回 `SUCCEEDED`，但 `/joint_states` 仍在
   零位，说明仅看 action 状态会误判执行。加入明确目标位置误差约束，并用实际反馈核验。
2. 将仿真初始值从原模型硬限位 `0 rad` 调到项目仿真值 `0.3 rad`，避免边界初始化。
3. DART 下一个联动关节实际停在 `-1 rad`。夹爪模式专用 world 改为 Bullet Featherstone，
   五个从动关节在动态实验中按 `+1/-1` 倍率跟随。裸臂的 DART 路径不变。
4. MoveIt 首次规划报告近闭合指端内部网格碰撞；SRDF 只排除了实验实际检测到的机构
   接触对。另为主动关节添加项目仿真加速度限值，使时间参数化可以完成。

## 尚未完成的合同

没有实现 RS485/Modbus 硬件驱动、抓取接触力、负载/工具标定与实机安全验收。
这些不是当前构建的完成状态，不能从仿真执行结果推断。
