# 2026-10-24 RM65B 阶段 2 固定随机障碍物场景构建与验收

## 范围与模块归属

本报告对应扩展方案阶段 2，不是原 Pick & Place 流水线的同名编号。本轮未调用 cheap-worker 或低价模型，没有连接实机。阶段 0、1 的既有结果保留，本轮只建设静态障碍物，暂不引入阶段 3 运行时真值同步、阶段 4 感知或阶段 6 候选扩展。

实现落在 `pick_place_sim`：

- `pick_place_sim/obstacle_scene.py`：纯 Python 生成器，版本 `rm65b-static-obstacles/1`，不导入 ROS/Gazebo；随机数仅在此处产生。
- `config/obstacles.yaml`：固定用例、随机参数及四类轴对齐 Box；配置属于仿真场景工具。
- `launch/obstacle_pick_place.launch.py`：新独立入口；生成完整归档，再把同一个 `geometry.yaml` 交给 Gazebo world 适配器和既有公共 SceneSync。
- `scripts/obstacle_preflight.py`：一次性启动检查；等待全部环境回查确认、目标初始化及完整近期 Gazebo 关节反馈，再调用 MoveIt 状态有效性服务。它不是动态碰撞监视器。
- 既有 `workbench_world.py` 从“三个 ID 必须相等”改为“包含三个工作台 ID”，允许追加障碍物；禁止覆盖原模板中的目标、标记和地面等实体。

公共几何格式、SceneSync、MTC、公共 runtime 和各公共入口没有修改。新增依赖只有仿真包的标准 `sensor_msgs`；没有增加自定义消息或通用批次协议。沿用既有环境就绪参数、完整 MTC 解及执行协调器。原 `workbench_pick_place.launch.py` 继续兼容。

## 场景配置与拒绝规则

默认随机配置为种子 42、5 个障碍物，高度 0.08–0.16 m，障碍物间 XY 净距至少 0.04 m；支撑边缘余量 0.005 m，机器人基座二维保留半径 0.32 m，抓取/放置目标外扩 0.12 m。它们是本轮小型回归配置，不是原方案中大障碍物尺寸例子的可行性证明。

形状 footprint：薄墙 0.04×0.30 m、方块 0.08×0.08 m、长方体 0.16×0.05 m、围栏段 0.02×0.18 m。中心 z 由所选支撑面顶高和障碍物高度计算；两个适配器不分别抽样。

常规场景拒绝越界、目标区域占用、基座保留区侵入、重叠和间距不足。随机最多尝试 5000 次，数量不足直接失败，不提交部分场景，不偷偷改种子。目标还必须落在配置支撑面上。几何合法仅标为 `candidate`，初始机器人碰撞检查失败不会发布启动就绪，完整任务是否可行由 MTC 独立检查。

完整归档保留种子、生成器版本、全部配置、预期类别、拒绝采样数、完整几何、SHA-256、任务配置和 world/base 安装偏移；`geometry.yaml`、`task.yaml`、`world.sdf` 保留实际输入/转换结果。`startup.json` 保存检查结论，`initial-joints.json` 保存实际用于检查的关节反馈。指定的归档目录必须不存在，防止覆盖已有证据。默认归档留在 `/tmp/rm65b-obstacles-*/scene`，路径会打印。

基准目录提供 `empty_baseline`、`semi_ring_table`、`single_wall`、`left_block`、`right_block`、`narrow_passage`、`blocked_pick`、`blocked_place`。后两种在目标或放置点放置 0.30 m 高方块，保留明确的区域占用。它们必须显式使用 `benchmark` 模式，启动就绪始终为 false，不启动抓放执行器；`/pick_place/execute` 返回 `success=False` 和占用原因。它们证明预期结构性阻塞会被拒绝，不把规划未启动写成规划器无解证明。

`narrow_passage` 两围栏间几何净隙为 0.07 m；场景名称只描述布局，不承诺机器人必须穿过此隙，绕行路径分类仍属于后续候选分析。

## 发现与修正

首次薄墙的 ROS CLI 运行检查遇到发现尚未稳定：直接 ROS 查询几何和规划正常，部分 CLI 话题/动作列表未发现。保留失败日志 `single_wall/`，在专用 domain 重启 CLI daemon、等待发现后重试 `single_wall-retry/`，两项运行检查和完整执行通过。没有改机器人控制器来掩盖检查失败。

首次种子 77 被启动门控拒绝，接触对是夹爪左右内连杆；随后只读场景检查已显示状态有效。原门控仅要求六轴名称，可能先于完整夹爪反馈。修正为等待全部六轴、驱动夹爪及五个 mimic 的实际 `/joint_states`，数据到达时间不超过 1 s，mimic 差值不超过 0.02 rad，直接用此反馈进行碰撞检查并归档；不补零、不归一化、不忽略自碰撞。缺数据和不一致数据仍保持拒绝。原失败归档 `random_seed_77/` 保留。

既有 MoveIt/附件 Gazebo 关闭时崩溃、旧节点重复 shutdown 等退出问题单列于日志，不作为执行通过的证据，也未扩大为本阶段生命周期框架。

## 结论与限制

阶段 2 在冻结静态已知几何与固定附着仿真范围内验收通过：生成器、共同快照、Gazebo/MoveIt 转换、结构筛选、启动碰撞门控、固定/随机/基准模式和预期负例拒绝均有独立证据。下一项仅应开展阶段 3 的静态场景运行时真值同步和更新失效验证。

任意种子、任意障碍尺寸、整个 U 台可达、真实接触、视觉、动态环境和实机均不在本结论内。腕部相机仍无经认证的碰撞模型，不能把 MoveIt 机器人物体碰撞结果写成相机/实机认证。
