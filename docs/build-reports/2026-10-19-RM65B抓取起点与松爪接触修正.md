# 2026-10-19 RM65B 抓取起点与松爪接触修正

## 变更

本轮处理两个验收问题：

1. 视觉观察位完成后，手动触发 `/pick_place/execute` 不应先回 `ready` 初始姿态。
2. 物体放置后打开夹爪，指垫不应因过高切向摩擦把物体拖走。

MTC 任务已删除抓取前的 `Home` 阶段。任务现在从 `CurrentState`（观察动作后的实际关节
状态）进入 `open gripper`、`Pre-Grasp (OMPL)` 和 `Approach (Cartesian)`；末尾的
`return Home` 保留。`auto_execute:=false` 只控制是否等待手动触发，不改变规划起点。

物理接触场景中的指垫和物体摩擦系数由 `4.0` 调为 `1.2`，左右指垫保持相同参数；模型
没有加入显式黏附力或固定附着。其余接触、质量和验收门限保持不变，便于把结果归因于摩擦
调整。

## 运行复测

干净视觉接触实例使用：

```bash
source scripts/source_pick_place_env.sh
ros2 launch pick_place_sim vision_pick_place.launch.py \
  headless:=true use_rviz:=false auto_execute:=false wrist_camera:=true
```

阶段 5 和阶段 6 通过：原生 RGB-D/TF/同步正常，Gazebo 真值误差 `0.001 m`，PlanningScene
同步误差 `0.000 m`。MTC 阶段 2 通过。

手动触发后，执行日志的第一段为 `Pre-grasp and approach (7 MTC stages)`，不再执行抓取前
初始化 Home。物理执行节点报告：

- 接近后物体偏差 `0.001 m`，未被接近动作推倒；
- 闭合后物体偏差 `0.003 m`，抬升后物体高度 `0.569 m`；
- 运输中物体到工具漂移 `0.004 m`；
- 松爪前物体到放置目标误差 `0.020 m`；
- 松爪后误差 `0.006 m`，撤退后仍为 `0.006 m`，未出现单指拖拽造成的持续位移；
- 最终 `Pick and Place completed`，`execution_success=true`，附件状态保持 `detached`。

上述执行节点结果证明本轮摩擦参数下完成了一次闭环，但单次通过不代表对其他物体、负载或
时间步长均稳定。阶段 4 verifier 已补充 `base_link -> world` 的 `0.15 m` 换算，并放宽了
中间 transient-local 状态的必需字符串检查；双侧指垫接触样本仍是硬门槛。当前三次执行的
执行节点均成功，但 verifier 尚未取得完整 PASS，因为接触传感器输出中没有稳定出现左右指垫
碰撞名称。该缺口不能用成功状态或物体最终位置替代。

补充的原始 Gazebo contact topic 为
`/world/empty/model/pick_object/link/body/sensor/grasp_contacts/contact`；静置和当前运行实例
中可见碰撞对为 `pick_object::body::collision` 与 `pick_table::top::collision`，未见
`left_pad`/`right_pad`。这只能证明当前传感器没有提供指垫碰撞证据，不能证明指垫没有发生物理接触；
下一轮应在执行窗口内同步捕获原始 topic，并检查指垫 collision 是否被传感器过滤。

## 使用结论

- 手动视觉执行从观察位规划，不再经过冗余的初始化姿态。
- 默认摩擦降为 `1.2` 是仿真接触参数，不能解释为真实胶垫材料标定。
- 真实接触仍须观察 `/pick_place/sim/object_pose`、姿态、接触状态和 PlanningScene；不要用
  MTC 规划成功或 attachment 状态替代物理抓取证据。

## 启动故障说明

若日志出现 `gz sim ... exit code -15`，先查找此前异常中断留下的 Gazebo/ROS launch 进程。
本轮复核中真正的首发错误是控制器 spawner 报 `Controller already loaded` 和
`Failed to configure controller`；launch 随后向 Gazebo 发送 SIGINT，等待超时后升级为
SIGTERM，因此 Gazebo 的 `-15` 只是被动清理结果。结束旧实例后重新启动即可避免该资源冲突。
